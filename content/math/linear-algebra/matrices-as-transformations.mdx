task: |
  Watch a matrix move a grid, then build one tiny "layer".

  **In Python (25 minutes, free Google Colab works).**

  ```python
  import numpy as np
  import matplotlib.pyplot as plt

  def show(M, title):
      xs, ys = np.meshgrid(np.arange(-3, 4), np.arange(-3, 4))
      pts = np.stack([xs.ravel(), ys.ravel()])  # 2 x 49 grid points
      out = M @ pts
      plt.figure(figsize=(4, 4))
      plt.scatter(pts[0], pts[1], s=8, c="lightgray")
      plt.scatter(out[0], out[1], s=8)
      plt.arrow(0, 0, M[0, 0], M[1, 0], color="green", width=0.05)  # where (1, 0) lands
      plt.arrow(0, 0, M[0, 1], M[1, 1], color="red", width=0.05)    # where (0, 1) lands
      plt.title(title); plt.axis("equal"); plt.show()

  show(np.array([[0, -1], [1, 0]]), "rotate 90 degrees")
  show(np.array([[1, 1], [0, 1]]), "shear")
  show(np.array([[1, 2], [2, 4]]), "dependent columns")

  W = np.array([[2, -1], [1, 3]])
  b = np.array([1, -2])
  x = np.array([3, 2])
  print("W @ x:", W @ x)
  print("by columns:", 3 * W[:, 0] + 2 * W[:, 1])
  print("layer:", np.maximum(0, W @ x + b))  # ReLU(W x + b)
  ```

Stop seeing a matrix as a grid of numbers. A matrix is a **function that moves space**:
it rotates, stretches, shears or squashes every vector at once. That one shift is the reason
"a neural network layer" stops being mysterious, because a layer's weights are exactly such a
function, learned from data.

## What makes a transformation linear

A transformation takes a vector in and gives a vector out. It is **linear** when two things hold:
straight lines stay straight, and the origin stays where it is. Picture a grid drawn on the
plane: after a linear transformation its lines are still parallel and evenly spaced, even if
they're tilted or stretched.

That rule has a big consequence. If v = −1·(first basis vector) + 2·(second basis vector)
before the move, then after it v lands at −1·(where the first landed) + 2·(where the second
landed). So you never need to track every point. **Where the basis vectors land decides
everything.**

## The matrix is the record of where they land

In two dimensions that's four numbers: two for where (1, 0) lands and two for where (0, 1)
lands. Write them as the two **columns** of a 2 × 2 matrix. To apply the matrix to a vector,
scale each column by the matching coordinate and add.

## Worked example: one matrix, two ways

Let W have columns (2, 1) and (−1, 3), and apply it to x = (3, 2).

1. **By columns.** 3·(2, 1) + 2·(−1, 3) = (6, 3) + (−2, 6) = **(4, 9)**.
2. **By rows** (the rule you may have memorized). Row one is (2, −1): 2·3 + (−1)·2 = 4. Row two
   is (1, 3): 1·3 + 3·2 = 9. Same answer.

The column reading tells you *why* it works. The row reading is often faster to compute and
leads straight to the dot product in → dot-product-duality.

Now scale up. A layer that maps a 4,096-wide vector to another 4,096-wide vector needs a
4,096 × 4,096 matrix: **16,777,216** weights, plus 4,096 biases. Stack enough layers like that
and you reach the billions behind a "7B model". Every forward pass multiplies through all of
them, which is why bigger matrices mean more memory and more compute per token.

## Where linearity stops

A neural-network layer computes `activation(W·x + b)`. Only `W·x` is linear. Adding the bias b
shifts every output, so the origin moves (the map is called affine). The activation, such as
ReLU, bends straight lines. That bend is what lets stacked layers represent more than a single
matrix could (→ neural-networks).

## Common mistakes

- **Reading rows as the "meaning".** Columns are where input directions go; read them first.
- **Calling a layer linear.** With a bias and an activation it isn't; only the matrix part is.
- **Ignoring dependent columns.** If columns line up, the map squashes space and some input
  differences can never be recovered (→ rank-column-null-space).
- **Multiplying entry by entry.** A matrix acts by combining columns, not by pairing numbers.

## Where you'll see it in AI

- **Every dense layer** is a learned matrix applied to a vector (→ neural-networks).
- **Queries, keys and values** in attention are three matrices applied to each token's vector
  (→ transformers-attention).
- **Parameter counts and cost:** model size is the sum of its matrices' entries
  (→ models-and-effort).
