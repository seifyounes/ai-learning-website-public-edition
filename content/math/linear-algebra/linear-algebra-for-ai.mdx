task: |
  Do the two operations by hand, then let a few lines of Python confirm them.

  **On paper (10 minutes).** Draw axes. Draw v = (2, 1) and w = (−1, 3). Draw v + w tip to tail
  and check it lands on (1, 4). Draw 2v, −v and 0.5w. Then compute the average of
  a = (4, 0), b = (0, 4) and c = (2, 2) by adding them and multiplying by 1/3. Where does the
  average point, and is it as long as the inputs?

  **In Python (10 minutes, free Google Colab works).**

  ```python
  def add(u, v):
      return [a + b for a, b in zip(u, v)]

  def scale(k, v):
      return [k * a for a in v]

  vs = [[4, 0], [0, 4], [2, 2]]
  total = [0, 0]
  for v in vs:
      total = add(total, v)
  print(scale(1 / len(vs), total))  # the average vector
  ```

  Change `vs` to two vectors that point in opposite directions, such as [3, 1] and [−3, −1],

**You need:** high-school algebra: multiplying, adding and reading a short formula. No
calculus, and no linear algebra beyond what this track builds.

This track re-reads linear algebra as the machinery inside the models you use. It starts with
the one object everything else acts on: the **vector**. An embedding, a token's hidden state, a
row of a dataset and a model's output scores are all vectors, so the habits you build in this
lesson carry through every later one.

## One object, two pictures

A vector is an **ordered list of numbers**: (2, 1), or (0.12, −0.40, 0.88, …) with 768
entries. It is also an **arrow** that starts at the origin and ends at the point those numbers
name. Each number says how far to go along one axis.

Neither picture is the "real" one. The list is what you store and compute with; the arrow is
what you reason with. When a search tool says two texts are "close", it means their arrows
point in similar directions. You can't draw 768 axes, but every rule you see in two dimensions
still holds there, which is why the flat picture is a trustworthy guide.

## The two operations

Everything in linear algebra is built from two moves.

- **Adding** two vectors: put the second arrow's tail on the first one's tip; the sum points to
  where you end up. In numbers, add matching entries.
- **Scaling** a vector by a number (a **scalar**): stretch it, shrink it, or flip it with a
  negative number. In numbers, multiply every entry.

Combine them and you get averages, blends and differences, which models use constantly.

## Worked example: averaging three embeddings

Real embeddings have hundreds of entries, but the arithmetic is the same in two. Say three
sentences of a paragraph embed to a = (4, 0), b = (0, 4) and c = (2, 2).

1. **Add.** a + b + c = (4 + 0 + 2, 0 + 4 + 2) = (6, 6).
2. **Scale by 1/3.** (6, 6) × 1/3 = **(2, 2)**.

The average points diagonally, between a and b, and it equals c, the sentence that was already
"in the middle". Now try two sentences that disagree: (3, 1) and (−3, −1). Their sum is (0, 0),
so the average is the zero vector, an arrow with no direction at all. That is the same reason a
chunk that covers several unrelated topics gets a vector that matches none of them well.

## Common mistakes

- **Treating one entry as a meaning.** A single coordinate of a learned embedding rarely stands
  for a human concept; meaning lives in the direction of the whole arrow (more on this in
  → change-of-basis-embeddings).
- **Forgetting that averaging dilutes.** Mean pooling, user profiles and chunk vectors are all
  averages; the more different the inputs, the shorter and vaguer the result.
- **Mixing vectors from different models.** Adding or comparing vectors only makes sense when
  they live in the same space, which means the same model (and version) produced them.
- **Reading a negative scalar as "less".** Multiplying by −1 doesn't shrink an arrow; it
  reverses it.

## Where you'll see it in AI

- **Embeddings and search:** every text, image or item becomes a vector, and search compares
  arrows (→ cosine-similarity-search, → embeddings-vector-databases).
- **Mean pooling:** many embedding models turn a sequence of token vectors into one vector by
  averaging them, which is the worked example above.
- **Residual connections:** a transformer layer adds its output back onto its input vector,
  tip to tail (→ transformers-attention).
- **Training updates:** a gradient step scales a direction by the learning rate and adds it to
  the weights (→ calculus-for-optimization).
