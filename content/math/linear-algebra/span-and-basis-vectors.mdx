The last lesson gave you two operations: adding vectors and scaling them. This one asks what
they can build. The answer has a name, the **span**, and it decides what a set of vectors can
and can't express. That matters in AI because many model outputs are built by mixing a few
vectors, and many datasets carry columns that add nothing new.

## Coordinates are instructions to scale

Read the vector (3, −2) differently: take the unit vector along x and stretch it by 3; take
the unit vector along y, flip it and stretch it by 2; add the two. The two unit vectors are the
**basis**, and the coordinates are the scalars that act on them.

Nothing forces that choice. Any two vectors that don't line up can serve as a basis, and they
give a different but equally valid set of coordinates for the same arrows. So a list of numbers
only means something together with the basis it was measured in.

## Linear combinations and span

Scaling some vectors and adding the results is a **linear combination**. The **span** of a set
of vectors is everything you can reach that way. In the plane, two vectors that point different
ways span the whole plane; two that line up span only a line.

In three dimensions, two vectors span a flat sheet through the origin. A third vector either
sits on that sheet (and adds nothing) or points off it (and unlocks all of space). When a vector
adds nothing, the set is **linearly dependent**: one vector is a combination of the others. When
each one adds a new direction, the set is **linearly independent**. A **basis** is an
independent set that spans the whole space.

## Worked example: reaching a target

Take v₁ = (1, 2) and v₂ = (3, 1). Can you reach (5, 5)? You need a and b with
a·(1, 2) + b·(3, 1) = (5, 5), one equation per coordinate:

1. First coordinate: a + 3b = 5.
2. Second coordinate: 2a + b = 5, so b = 5 − 2a.
3. Substitute: a + 3(5 − 2a) = 5, so 15 − 5a = 5 and **a = 2**, then **b = 1**.

Check: 2·(1, 2) + 1·(3, 1) = (2, 4) + (3, 1) = (5, 5). Now swap v₂ for (2, 4). That is just
2·v₁, so both vectors lie on one line through the origin, and (5, 5) is not on it: no choice of
a and b works. Same number of vectors, much smaller span.

## Common mistakes

- **Counting vectors instead of directions.** Ten vectors can span only a plane if they all lie
  on it. What matters is how many are independent.
- **Assuming a big space means a big span.** Vectors with 1,024 entries still span at most as
  many dimensions as there are vectors.
- **Treating coordinates as absolute.** The same arrow has different numbers in a different
  basis (→ change-of-basis-embeddings).
- **Calling any related column "dependent".** Linear dependence means an exact scaled sum.
  Height, weight and BMI are related, but BMI is not a linear combination of the other two.

## Where you'll see it in AI

- **Attention outputs:** each output is a weighted sum of value vectors, so it lies in their
  span (→ transformers-attention).
- **Redundant features:** dependent columns make a linear model's weights unstable, because
  many different weightings give the same predictions (→ machine-learning-fundamentals).
- **Rank and low-rank tricks:** the number of independent directions in a set is the rank,
  which → rank-column-null-space turns into the idea behind LoRA.
- **Embedding spaces:** a model's d-dimensional embeddings use some basis it learned, which is
  why single coordinates are hard to read.
