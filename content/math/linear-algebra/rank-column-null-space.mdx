  Solve a system both ways, find a null space, then build a LoRA-style update and count it.

  **On paper (10 minutes).** Solve 2x + y = 5 and x + 3y = 5. Then take the matrix with columns
  (1, 2) and (2, 4): find one vector that it sends to zero, and decide whether A·x = (3, 6) and
  A·x = (3, 5) have solutions.

  **In Python (20 minutes, free Google Colab works).**

  ```python
  import numpy as np

  A = np.array([[2.0, 1.0], [1.0, 3.0]])
  v = np.array([5.0, 5.0])
  print("solution:", np.linalg.solve(A, v))

  S = np.array([[1.0, 2.0], [2.0, 4.0]])          # columns (1, 2) and (2, 4)
  print("rank of S:", np.linalg.matrix_rank(S))
  print("S @ (2, -1):", S @ np.array([2.0, -1.0]))

  d, r = 1024, 8
  B = np.random.randn(d, r)                     # tall and thin
  C = np.random.randn(r, d)                     # short and wide
  delta = B @ C                                 # a full d x d update
  print("update shape:", delta.shape, "rank:", np.linalg.matrix_rank(delta))
  print("numbers stored: full", d * d, "vs low-rank", B.size + C.size)
  ```

The determinant told you whether a transformation squashes space. This lesson names what
happens next: whether you can **undo** it, how much of the output space it actually **reaches**,
and which inputs it **erases**. One of those words, **rank**, is the reason a whole family of
fine-tuning methods is cheap.

## Solving equations is "which input lands here?"

A system like 2x + y = 5 and x + 3y = 5 only scales the unknowns and adds them, so it packs into
one matrix equation A·x = v. Read geometrically: A moves space, and you want the input x that
lands on v.

If det(A) isn't zero, exactly one input works, and you find it by playing the transformation
backwards. That backwards move is the **inverse**, A⁻¹. Doing A and then A⁻¹ gives the
**identity**, the transformation that changes nothing.

If det(A) is zero, there's no inverse: space was squashed onto a line (or plane, or point), and
no function can spread a line back out into a plane. A solution exists only if v happens to lie
in what's left.

## Rank, column space and null space

- **Column space:** every possible output, which is the span of the matrix's columns.
- **Rank:** the number of dimensions of the column space. Full rank means nothing was squashed.
- **Null space:** every input that lands on the zero vector. For a full-rank matrix it's just
  zero itself; otherwise it's a whole line, plane or more. Inputs that differ by a null-space
  vector give the same output.

## Worked example: one full-rank system, one squashed one

**Full rank.** A has columns (2, 1) and (1, 3), so det = 2·3 − 1·1 = 5. The inverse is
(1/5) times the matrix with rows (3, −1) and (−1, 2). Applied to v = (5, 5): (1/5)·(15 − 5,
−5 + 10) = **(2, 1)**. Check: 2·2 + 1 = 5 and 2 + 3·1 = 5.

**Rank 1.** S has columns (1, 2) and (2, 4). The second is twice the first, so the column space
is the line through (1, 2) and the rank is 1. The vector (2, −1) lands on 2·(1, 2) − 1·(2, 4) =
(0, 0), so the null space is the line through (2, −1). Then S·x = (3, 6) has infinitely many
solutions, such as (3, 0) and (1, 1), while S·x = (3, 5) has none, because (3, 5) isn't on the
line.

## Why LoRA is cheap

Fine-tuning changes a big weight matrix W by some update ΔW. **LoRA's bet** is that the useful
update has **low rank**: it only needs a few independent directions. So instead of learning all
4,096 × 4,096 ≈ 16.8 million entries of ΔW, it learns a tall 4,096 × 8 matrix times a wide
8 × 4,096 one: 65,536 numbers, about 256 times fewer. Their product is a full-size matrix of
rank at most 8. How those tall and wide shapes work is the topic of
→ nonsquare-matrices-dimensions.

## Common mistakes

- **Concluding "no solution" from det = 0.** There's no inverse; solutions may still exist.
- **Reading rank as a count of non-zero entries.** It counts independent directions.
- **Inverting to solve.** Software solves A·x = v directly (more accurate and faster) rather than
  forming A⁻¹.
- **Assuming low rank always works.** It's a bet; evaluation tells you whether r is big enough.

## Where you'll see it in AI

- **LoRA and adapters:** low-rank updates for fine-tuning (→ fine-tuning-fundamentals).
- **Compression:** keeping only the strongest directions of a matrix is the idea behind the SVD
  lectures linked from → eigenvectors-eigenvalues.
- **Information loss in layers:** a projection to a lower rank erases its null space, so later
  layers can't recover it (→ neural-networks).
- **Least squares:** when there's no exact solution, regression finds the closest point in the
  column space (→ machine-learning-fundamentals).
