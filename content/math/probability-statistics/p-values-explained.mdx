task: |
  Run an A/A test: the same prompt twice, many times, and count the "significant" results.

  ```python
  import random
  from math import sqrt, erf

  def p_value(x1, x2, n):
      p1, p2 = x1 / n, x2 / n
      pooled = (x1 + x2) / (2 * n)
      se = sqrt(2 * pooled * (1 - pooled) / n)
      if se == 0:
          return 1.0
      z = abs(p1 - p2) / se
      return 2 * (1 - 0.5 * (1 + erf(z / sqrt(2))))  # two-sided

  false_pos = 0
  for _ in range(1000):
      a = sum(random.random() < 0.8 for _ in range(100))  # same prompt...
      b = sum(random.random() < 0.8 for _ in range(100))  # ...run twice
      if p_value(a, b, 100) < 0.05:
          false_pos += 1
  print("false positives out of 1000:", false_pos)
  print("p for 84 vs 88 of 100:", round(p_value(84, 88, 100), 3))
  ```

**You need:** the null hypothesis. → hypothesis-testing-null first.

A **p-value** answers one narrow question: if there were really no difference, how often would
you see a result at least as extreme as this one? A small p-value means "chance alone would
rarely do this", which is a reason to reject the null. It's useful, and it's misread constantly,
including in AI evals and research papers. This lesson is about reading it right.

## What it is and what the threshold controls

The p-value runs from 0 to 1. Close to 0: the data would be surprising if nothing were going on.
Large: the data is ordinary under "no difference".

You pick a **threshold** in advance, commonly 0.05. Its meaning: when there really is no
difference, about 5% of experiments will still cross it. Those are **false positives**. The
threshold is a choice about how many false positives you'll tolerate:

- costly mistake (shipping a medical model, a risky migration): use a much smaller threshold;
- cheap mistake (triggering a quick manual check): a looser one is fine.

## Two traps

**Size.** A p-value mixes the size of a gap with the amount of data. With 100,000 users per arm,
a thumbs-up rate moving from 50.0% to 50.5% gives p ≈ 0.025: significant, and possibly not worth
anything. With 100 examples per prompt, 84% versus 88% gives p ≈ 0.4: not significant, and
possibly a real 4 points. Always report the gap and its interval alongside the p-value.

**Many tries.** Every test at 0.05 has a 5% chance of a fluke. Test many things and flukes
become likely.

## Worked example: twenty prompt variants

You write 20 rewordings of a system prompt and test each against the original at 0.05. Suppose
none of them is truly better.

1. Chance that a single test stays clean: 0.95.
2. Chance all 20 stay clean: 0.95²⁰ ≈ 0.36.
3. Chance **at least one** looks significant: 1 − 0.36 ≈ **0.64**.

So in this situation it's more likely than not that you'd "find" a winner that is pure luck. Two
simple defences: re-test the winner alone on fresh examples, or divide the threshold by the number
of comparisons (0.05 ÷ 20 = 0.0025 per test, the Bonferroni correction).

The same applies to checking many metrics, many slices of users or many checkpoints of a
training run: the more you look, the more chance results you'll see.

## Common mistakes

- **"p = 0.03 means a 3% chance the null is true."** No: it's the chance of data this extreme if
  the null were true.
- **Treating p > 0.05 as proof of no difference.** It's a failure to reject, often from small n.
- **Equating a small p-value with a big effect.** Check the size separately.
- **Reporting only the variant that worked.** Say how many you tried.
