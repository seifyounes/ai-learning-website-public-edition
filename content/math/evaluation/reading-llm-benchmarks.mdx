task: |
  Find the noise band around a benchmark score.

  ```python
  import math, random

  n = 500  # questions in the benchmark
  a, b = 0.81, 0.79  # two models' scores
  se_a = math.sqrt(a * (1 - a) / n)
  se_b = math.sqrt(b * (1 - b) / n)
  se_gap = math.sqrt(se_a**2 + se_b**2)  # standard error of the difference
  print(f"gap {(a - b) * 100:.1f} points, 95% band ± {1.96 * se_gap * 100:.1f} points")

  # one model with a true skill of 81% takes ten fresh 500-question tests
  random.seed(1)
  print([sum(random.random() < 0.81 for _ in range(n)) / n for _ in range(10)])
  ```

  1. Run it (any online Python runner) or compute the first part by hand with a calculator.
  2. Look at the ten simulated scores of a single model. How far apart are the highest and the
     lowest?
  3. Open any public LLM leaderboard, find two models within 2 points of each other, and look up
     how many questions that benchmark has. Work out each score's standard error, combine them
     as √(SE_A² + SE_B²), and decide whether the gap is bigger than 1.96 times that.

  Success: a band of about ±5 points on the gap between two scores from 500 questions, and a
  written verdict on whether the leaderboard gap you found is bigger than the noise.

Every model release comes with a table of benchmark scores, and every leaderboard ranks models
by them. They're useful, and easy to over-read. A benchmark score is **one test, run one way,
scored one way**, with noise around it. This lesson is how to read one without being fooled,
and why it can only shortlist a model for your job.

## Three parts of every benchmark

1. **The test data:** a fixed set of questions, documents or coding problems.
2. **How the model is run:** zero-shot (no examples), few-shot (a few worked examples in the
   prompt) or fine-tuned. The same model scores differently under each.
3. **How answers are scored:** exact match, accuracy, unit tests passed, or a judge. Often several
   are combined into one score from 0 to 100.

Change any of the three and you have a different number. Before comparing two scores, check
that all three match.

## Worked example: is a 2-point lead real?

A benchmark has 500 questions. Model A scores 81%, model B 79%. Treat each score as a sample
proportion:

1. Standard error of each score ≈ √(0.8 × 0.2 ÷ 500) = √0.00032 ≈ 0.018, so about **1.8
   points**.
2. The question is about the **gap**, and both scores are noisy, so their errors combine: SE of
   the gap ≈ √(1.8² + 1.8²) = √2 × 1.8 ≈ **2.5 points**.
3. A 95% band on the gap is about ±1.96 × 2.5 ≈ **±5 points**. The 2-point gap sits well inside
   it. Run a fresh 500 questions and the order could flip.

With 5,000 questions each standard error drops to about 0.57 points, the gap's to about 0.8, and
its band to about ±1.6 points, because they fall with the square root of the number of
questions. Small benchmarks can't separate close models.

If you have both models' per-question results, a **paired** comparison on the same questions is
tighter: questions both get right or both get wrong add no noise to the gap, only the ones where
they disagree do. If they disagree on 50 of the 500, the gap's standard error is about
√(0.10 ÷ 500) ≈ 1.4 points, a band of about ±2.8: tighter, but still wider than 2.

## pass@k: capability vs consistency

Coding benchmarks often report **pass@k**: the probability that at least one of k samples
passes the tests. A big gap between pass@1 and pass@10 means the model *can* solve the task but
doesn't do it reliably on the first try. That gap is what justifies generating several answers
and keeping one that passes a checker.

## Three limits to keep in mind

- **Edge cases:** a general test rarely contains the unusual inputs your job depends on.
- **Overfitting and contamination:** if test questions leak into training data, or a model is
  tuned towards one test, the score stops measuring skill on new problems.
- **Short shelf life:** once top models max a benchmark, it no longer separates them, and newer,
  harder tests replace it.

## Common mistakes

- **Treating a 1–2 point lead as a ranking.** Check the number of questions first.
- **Comparing scores from different setups.** Few-shot vs zero-shot, pass@1 vs pass@10, a
  different answer parser.
- **Choosing a model for your task from a general benchmark alone.** It's a shortlist.
- **Reading an old benchmark as current.** A maxed-out test says little about today's models.
