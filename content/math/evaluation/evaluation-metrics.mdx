task: |
  Draw a ROC curve and compute AUC from eight scores.

  ```python
  pos = [0.95, 0.80, 0.60, 0.35]   # scores the model gave real positives
  neg = [0.70, 0.40, 0.20, 0.10]   # scores it gave real negatives

  for t in [0.9, 0.75, 0.65, 0.5, 0.38, 0.3, 0.15, 0.0]:
      tpr = sum(s >= t for s in pos) / len(pos)
      fpr = sum(s >= t for s in neg) / len(neg)
      print(f"threshold {t:.2f}: FPR {fpr:.2f}, TPR {tpr:.2f}")

  wins = sum(p > n for p in pos for n in neg)
  print("AUC =", wins / (len(pos) * len(neg)))
  ```

  1. Before running it, plot the eight (FPR, TPR) points on paper or graph paper and join them.
  2. Run the code (any online Python runner works) or rebuild it in a spreadsheet, and check
     your points.
  3. Count by hand: of the 16 positive–negative pairs, how many have the positive scored higher?
     Compare that share with the printed AUC.
  4. Pick the threshold you'd ship if a false alarm costs ten times more than a miss.

**You need:** sensitivity from → sensitivity-specificity and precision from
→ precision-recall-tradeoff.

Most classifiers don't output "yes" or "no". They output a score, and **someone chooses the
threshold** that turns it into a decision. Each threshold gives a different confusion matrix.
The ROC curve puts all of them on one picture, and AUC sums that picture up as one number for
comparing models. The threshold you finally run at is a product decision, not a default.

## From one table to a curve

Every threshold produces two rates:

- **True-positive rate (TPR)** = sensitivity = TP ÷ (TP + FN), on the y-axis.
- **False-positive rate (FPR)** = 1 − specificity = FP ÷ (FP + TN), on the x-axis.

A threshold so low that everything is "yes" sits at (1, 1); one so high that nothing is "yes"
sits at (0, 0). Every threshold in between is a point, and joining them gives the curve. The
diagonal is a coin flip. The further the curve bows towards the top-left corner, the better
the model separates the two classes.

## Worked example: eight scores

A model scores four real positives (0.95, 0.80, 0.60, 0.35) and four real negatives (0.70,
0.40, 0.20, 0.10). Say "yes" when the score is at or above the threshold:

1. Threshold 0.75: two positives caught, no negatives. Point (0, 0.5).
2. Threshold 0.5: three positives, plus the 0.70 negative. Point (0.25, 0.75).
3. Threshold 0.3: all four positives, plus two negatives. Point (0.5, 1).

Now AUC. It equals the share of positive–negative pairs where the positive gets the higher
score. Of the 4 × 4 = 16 pairs, the positive wins 4 + 4 + 3 + 2 = **13**, so AUC = 13 ÷ 16 ≈
**0.81**. That reading is the useful one: pick a random positive and a random negative, and
the model ranks them correctly 81% of the time. 0.5 is guessing, 1.0 is perfect separation.

## The threshold is a product decision

Compare models by AUC; *operate* at the one threshold whose error mix matches your costs. If a
miss is dangerous and a follow-up is cheap, lower it. If false alarms burn people's time or
trust, raise it. Write the reason down, because the next person will ask why it isn't 0.5.

## When ROC flatters

The false-positive rate divides by all the negatives, so when negatives are plentiful it stays
tiny. Take a hypothetical 100,000 transactions with 500 frauds. A threshold that catches 400
frauds (TPR 0.8) at an FPR of 2% looks excellent on a ROC plot. But 2% of 99,500 honest
transactions is **1,990** false alarms, so precision is 400 ÷ 2,390 ≈ **17%**: five of every six
flags are wrong. For rare positives, read the precision-recall curve and the precision at
your real threshold.

## Common mistakes

- **A great ROC-AUC and a flood of false alarms** → rare positives make the FPR look small →
  read the PR curve and the precision at your threshold.
- **Reading AUC as accuracy.** It's ranking quality across all thresholds; it says nothing about
  any single cutoff.
- **Shipping the highest-AUC model blindly.** Curves can cross. Compare at the FPR you can afford.
- **The threshold was never chosen, just inherited** → pick it from the curve, by cost.

## Where you'll see it in AI

- **Moderation and safety classifiers:** category scores with a cutoff you set.
- **Retrieval:** a similarity cutoff for which chunks reach the model is a threshold on a score
  (→ embeddings-vector-databases).
- **Calibration:** a threshold only means what you think if scores are calibrated
  (→ conditional-probability-counts).
- **Model selection:** AUC to shortlist, then one operating point, then one agreed number for the
  team (→ single-number-metric).
