The one idea of this lecture: **a network "learning" means minimising a cost function by
repeatedly nudging every weight a little against the gradient.** Once you see it that way,
training stops feeling like magic and starts feeling like the calculus of the previous six
lessons, run in a loop.

## From a network to one number

The lecture's network reads a 28×28 image (784 inputs) and produces 10 outputs, with about
13,000 weights and biases in between. For one training image, the **cost** adds up the squared
gaps between the 10 outputs and the right answer (1 for the true digit, 0 for the rest). Average
that over every training image and you get a single number that depends on all 13,000 weights.
That's the loss curve on every training dashboard.

There's no formula for the best 13,000 weights. So you start from random weights and ask the
gradient which way is downhill:

```text
w ← w − learning_rate × ∇loss(w)
```

Step, recompute, repeat. Where you start decides which valley you end in, and nothing promises
the lowest one. Read each gradient entry as two facts: the sign says which way to move that
weight, the size says how much that weight matters right now.

## Worked example: train a one-weight model by hand

A model predicts `w × x`; one example has x = 2 and y = 6, so the perfect weight is 3. The
loss is `(w × x − y)²` and its gradient, from → chain-rule-and-product-rule, is `8w − 24`.

1. **Learning rate 0.05, start at w = 0.** Gradient −24, so w becomes **1.2**. Next gradient
   −14.4, so w = **1.92**. Then **2.35**, then about **2.61**. Each step closes 40% of the gap.
2. **Learning rate 0.3.** Gradient −24, so w jumps to **7.2**, past 3. Next gradient 33.6, so
   w = **−2.88**. Then about 11.2. The error grows 1.4× per step, flipping sign each time:
   the "loss exploded to NaN" story at the size of one number.

For this loss each step multiplies the error by `(1 − 8 × lr)`, so anything above lr = 0.25
diverges. Real models have no tidy formula like that, which is why learning rates are found by
trial runs and schedules (→ learning-rate-decay-schedules).

> 💡 **Try it:** sketch a U-shaped valley on paper. Draw the update steps for a small LR (short
> hops down one wall) and a huge LR (leaping across the valley to a HIGHER point on the other
> wall, then higher again). You've just drawn every "my loss exploded" incident ever filed.

## Reading loss curves

- Loss flat from the start → LR too small, or data/labels broken.
- Loss oscillates or explodes → LR too high.
- Train ↓ while validation ↑ → overfitting; stop early or regularise.
- Both plateau above target → a model or data capacity problem, not an optimiser problem.

The lecture's own result shows why the validation curve matters: the network gets about 96% of
unseen digits right, yet it confidently labels random noise as a digit, and (from the interview)
large networks can drive training cost down even on shuffled labels by memorising them.

## Common mistakes

- **Loss turns NaN after a few hundred steps** → LR too high, often with no warmup → cut the
  LR 3–10×, and turn on gradient clipping if your tool offers it.
- **Loss never moves** → LR far too small, or labels missing or masked out → run a short LR
  sweep, and print five training examples exactly as the model sees them.
- **Judging a run by training loss alone** → it can fall through memorisation; always watch a
  held-out curve.
- **Expecting the global minimum** → descent finds *a* valley, and different seeds can find
  different ones.

## Where you'll see it in AI

- **Every training and fine-tuning run** is this loop (→ fine-tuning-fundamentals).
- **The gradient itself** is computed by backpropagation (→ backprop-chain-rule-calculus).
- **Real runs** estimate it on mini-batches (→ mini-batches-and-epochs) and use smarter steps
  (→ momentum-optimizer, → adam-optimizer).
- **Evals** exist because training loss can lie (→ evaluation-metrics).
