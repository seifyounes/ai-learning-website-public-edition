  1. By hand: for f(x, y, z) = x²y + yz + 3z, write the three partials and evaluate the gradient
     at (1, 2, 3).
  2. Check it with a small reusable function:

     ```python
     def numerical_gradient(f, point, h=1e-6):
         grad = []
         for i in range(len(point)):
             up, down = list(point), list(point)
             up[i] += h
             down[i] -= h
             grad.append((f(*up) - f(*down)) / (2 * h))
         return grad

     f = lambda x, y, z: x ** 2 * y + y * z + 3 * z
     print(numerical_gradient(f, [1, 2, 3]))
     ```

**You need:** → partial-derivatives-many-inputs.

The one idea of this lecture: **the gradient is all of a function's partial derivatives
collected into one vector.** In the training update `w ← w − learning_rate × ∇loss`, the `∇loss`
is exactly this vector: one entry per weight, each saying how the loss responds to that weight.

## From partials to one vector

For `f(x, y) = x² sin y`:

- `∂f/∂x = 2x sin y` (freeze y)
- `∂f/∂y = x² cos y` (freeze x)

The gradient stacks them:

```text
∇f(x, y) = [ 2x·sin y ,
             x²·cos y ]
```

It's a **vector-valued function**: give it a point, get back a vector with one entry per input.
Two inputs give two entries; a model with 13,000 weights (the size of the digit network in
→ calculus-for-optimization) gives 13,000. The symbol `∇` is "nabla", read "del". A good memory
aid is to think of it as a vector of partial-derivative operators, `[∂/∂x, ∂/∂y, …]`, applied
to f.

The lecture warns that this computation looks unrelated to what the gradient *means*. That's
true, and → gradient-steepest-ascent closes the gap.

## Worked example with real numbers

**The lecture's function.** At (2, π/6), where `sin(π/6) = 0.5` and `cos(π/6) ≈ 0.866`:

```text
∇f = [2·2·0.5, 4·0.866]
   = [2, 3.464]
```

**One training step.** A model predicts `w1·x1 + w2·x2` with `x = [1, 3]` and target 10; the
loss is `(prediction − 10)²`. At `w = [1, 1]` the prediction is 4, the error is −6 and the loss
is 36. From the previous lesson, each partial is `2 × error × feature`:

```text
∇loss = 2·(−6)·[1, 3]
      = [−12, −36]
```

Update with learning rate 0.01:

| | w1 | w2 | prediction | loss |
|---|---|---|---|---|
| before | 1.00 | 1.00 | 4.0 | 36.00 |
| after | 1.12 | 1.36 | 5.2 | 23.04 |

One step with the whole vector moved both weights at once, each by an amount proportional to
its partial, and the loss fell by more than a third.

## Common mistakes

- **Mixing up the gradient and the step.** The gradient points uphill; the update subtracts it.
- **Reusing an old gradient.** It depends on the point; recompute after every update.
- **Thinking ∇ only works in 2D.** Pictures stop at two inputs; the vector doesn't.
- **Expecting zero output to mean zero gradient.** `x² sin y` is 0 at (3, 0) but its gradient
  there is [0, 9].

## Where you'll see it in AI

- **Every training step** computes this vector for all the weights (→ calculus-for-optimization).
- **Memory budgets:** the gradient has as many entries as the model has weights, which is part
  of why training needs far more memory than running a model (→ adam-optimizer).
- **Gradient norm** (the vector's length) is a standard training metric
  (→ gradient-steepest-ascent explains what that length means).
