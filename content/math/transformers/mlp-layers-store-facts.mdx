  Build the "Michael Jordan" neuron with numbers and watch the bias turn it into an AND gate.

  Use a 3-number embedding: [Michael, Jordan, other]. One neuron's up-projection row is
  [1, 1, 0] with bias −1. Its down-projection column writes the "basketball" direction.

  ```python
  import numpy as np

  row, bias = np.array([1, 1, 0]), -1.0
  basketball = np.array([0.0, 0.0, 1.0])

  def mlp(x):
      activation = max(0.0, row @ x + bias)   # up-projection, bias, ReLU
      return x + activation * basketball      # down-projection, added back

      "Michael Phelps": np.array([1.0, 0.0, 0.0]),
      "Jordan Peele":   np.array([0.0, 1.0, 0.0]),
  }.items():
      print(name, "->", mlp(x))
  ```

Each transformer block has two halves. Attention (→ query-key-value-attention) lets tokens
exchange information. Then a **multilayer perceptron (MLP)** transforms every token's vector
on its own, with the same weights at every position. The MLPs hold most of a model's
parameters, and they're a likely home for much of what it "knows". If you want to understand
why models half-remember facts, this is the place to look.

## Three steps per token

1. **Up-projection.** Multiply the vector by a large matrix that makes it several times
   longer (in GPT-3, from 12,288 to 49,152 numbers), and add a bias. Each row of the matrix
   takes a dot product with the vector, which you can read as asking one question: "does this
   vector point in my direction?"
2. **Nonlinearity.** Apply ReLU (or a smooth relative like GELU): negative values become 0.
   Each of the long vector's entries is one **neuron**; positive means it's firing.
3. **Down-projection.** Multiply by a second matrix back to embedding size. Each firing neuron
   adds its column, a direction in meaning space, to the result, which is then **added to the
   token's vector** (the residual connection).

```diagram
token vector (12,288)
   │
   ▼
× W_up + bias
   49,152 questions
   │
   ▼
ReLU
   negatives → 0
   │
   ▼
× W_down
   back to 12,288
   │
   ▼
add to the token vector
```

## Worked example: a neuron that knows one fact

Give the embedding three numbers: [Michael, Jordan, other]. One neuron's up-projection row is
[1, 1, 0] and its bias is −1.

- "Michael Jordan" [1, 1, 0]: 1 + 1 − 1 = **1**. ReLU keeps 1, so the neuron fires and adds its
  down-projection column, the "basketball" direction.
- "Michael Phelps" [1, 0, 0]: 1 − 1 = **0**. Nothing is added.
- "Jordan Peele" [0, 1, 0]: also **0**.

The bias makes the neuron an AND gate. At bias 0, each single name would score 1 and fire.

Scale it up: the up-projection has 12,288 × 49,152 ≈ **604 million** weights, and the
down-projection the same, so one MLP is about **1.2 billion**. Across GPT-3's 96 layers that's
about **116 billion** of its 175 billion parameters, roughly two thirds.

## Superposition: why neurons are hard to read

The clean "one neuron, one fact" picture is too tidy. In a space with thousands of dimensions
you can fit vastly more directions that are *nearly* perpendicular (say, between 89° and 91°)
than directions that are exactly perpendicular. A model can use that to store many more
features than it has neurons, each spread over many neurons. The cost is a little
interference, and the result is that a single neuron usually responds to a mix of unrelated
things.

## Common mistakes

- **Treating the MLP as a database.** Nothing is stored as a row you can edit; it's spread
  across weights.
- **Expecting one neuron per concept.** Superposition makes most neurons mixtures.
- **Forgetting the residual add.** The MLP's output is added to the token's vector, so each
  block refines rather than replaces.

## Where you'll see it in AI

Parameter counts and memory (most weights are MLP weights), mixture-of-experts models that
route each token to a few of many MLPs, interpretability research on features, and the
"retrieve, don't fine-tune facts" rule in → rag-fundamentals and
→ fine-tuning-fundamentals. You'll write the same block in code in → build-gpt-from-scratch.
