task: |
  Build the simplest possible next-word predictor and sample from it, so "a distribution over
  the next word" stops being abstract.

  ```python
  import random
  from collections import Counter, defaultdict

  text = """paste two or three paragraphs of any text here, the more the better"""
  words = text.lower().split()

  # Count which word follows which: a bigram table.
  follows = defaultdict(Counter)
  for a, b in zip(words, words[1:]):
      follows[a][b] += 1

  def next_word_probs(word):
      counts = follows[word]
      total = sum(counts.values())
      return {w: round(c / total, 2) for w, c in counts.most_common(5)}

  print(next_word_probs("the"))

  # Generate 15 words by sampling, then run it again.
  word = "the"
  out = [word]
  for _ in range(15):
      options = follows[word]
      if not options:
          break
      word = random.choices(list(options), weights=options.values())[0]
      out.append(word)
  print(" ".join(out))
  ```

  Run the generation three times and compare. Then change `random.choices(...)` to always take
  `options.most_common(1)[0][0]` and run it again.

  **No-code path:** take one paragraph, and in a spreadsheet list every word that follows "the"
  with its count; divide each count by the total to get probabilities.

  Success: you can point at the line that makes two runs differ, and say what the
  always-most-likely version loses.

A large language model computes one thing: **given some text, a probability for every possible
next word** (strictly, the next token). Everything else you see, chat, code, essays, is that one
prediction run in a loop. Hold onto this before you open the transformer: every part of the
architecture exists to make that one prediction better.

## From predictor to chatbot

A chatbot is built around the predictor, not inside it. The app writes a short opening that
describes an assistant, places your message after it like a line in a script, and asks the
model to continue as the assistant would. The model produces a distribution, the app picks a
word from it, appends that word, and asks again. The reply you read is dozens or hundreds of
those picks in a row.

The pick is usually **sampled**, not the single most likely word. Always taking the top word
tends to produce flat, repetitive text, so apps let less likely words through some of the time.
That is why the same prompt can give different answers.

## Worked example: sampling one word

Suppose that after "I drink my coffee with", the model's top five next words are:

| next word | probability |
|---|---|
| milk | 0.45 |
| sugar | 0.25 |
| cream | 0.15 |
| friends | 0.10 |
| oat | 0.05 |

These numbers are made up for illustration, but the mechanics are real:

- **Greedy decoding** always takes "milk". Ask 100 times, get "milk" 100 times.
- **Sampling** takes "milk" about 45 times out of 100, "sugar" about 25, and "friends" about 10.
  Each choice changes every later prediction, so two replies can drift far apart after a few
  words.
- A 300-word reply is about 300 of these draws (more, counted in tokens), each conditioned on
  everything chosen so far.

## Where the predictions come from

The probabilities come from a function with an enormous number of adjustable numbers,
**parameters** (or weights). Nobody sets them by hand. Training starts them at random, shows
the model real text, measures how much probability it gave the word that actually came next,
and uses backpropagation (→ backprop-intuition) to nudge every parameter so that word becomes a bit
more likely. Repeated over a vast amount of text, that is **pretraining**. The scale is hard
to picture: the lecture estimates that a person reading GPT-3's training text nonstop would
need over 2,600 years. A second stage, reinforcement learning from human feedback, has people
flag unhelpful answers and tunes the model toward replies they prefer.

The architecture that made this scale is the **transformer**. It reads every position of the
text at once instead of word by word, turns each token into a vector, and refines those
vectors through layers of **attention** (tokens exchange information) and **feed-forward
networks** (each token is transformed on its own). The rest of this track opens those boxes
one at a time.

## Common mistakes

- **Treating one answer as "what the model thinks".** It's one sample; another sample can
  differ, and the disagreement is informative.
- **Assuming the chatbot learns from your chat.** The parameters are fixed while you use it;
  only what's in the context changes.
- **Picturing a database lookup.** The model stores no list of facts to retrieve; it produces
  probabilities from parameters shaped by training.
