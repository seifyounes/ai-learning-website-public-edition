task: |
  Prove to yourself that attention ignores word order, then fix it with positional encoding.

  ```python
  import numpy as np

  rng = np.random.default_rng(0)
  d = 4
  emb = {w: rng.normal(size=d) for w in ["squatch", "eats", "pizza"]}
  Wq, Wk, Wv = (rng.normal(size=(d, d)) for _ in range(3))

  def attention(X):
      Q, K, V = X @ Wq, X @ Wk, X @ Wv
      s = Q @ K.T / np.sqrt(d)
      w = np.exp(s) / np.exp(s).sum(axis=1, keepdims=True)
      return w @ V

  def pos_enc(n):
      pe = np.zeros((n, d))
      for pos in range(n):
          for i in range(0, d, 2):
              pe[pos, i] = np.sin(pos / 10000 ** (i / d))
              pe[pos, i + 1] = np.cos(pos / 10000 ** (i / d))
      return pe

  a = np.array([emb[w] for w in ["squatch", "eats", "pizza"]])
  b = np.array([emb[w] for w in ["pizza", "eats", "squatch"]])

  # Without positions: the vector computed for "squatch" is identical in both sentences.
  print(np.allclose(attention(a)[0], attention(b)[2]))
  # With positions added, it isn't.
  print(np.allclose(attention(a + pos_enc(3))[0], attention(b + pos_enc(3))[2]))
  ```

  This uses no mask, as in an encoder, to make the point clean. Then, on paper, compute the
  positional encoding of position 1 with d = 4 and check it against `pos_enc(3)[1]`.

  Success: the first line prints True, the second False, and you can say why in one sentence.

Modern chat models are **decoder-only transformers**: a single stack of masked self-attention
and feed-forward layers that reads your prompt and writes the reply with the same weights.
This lesson rebuilds that stack at toy size, with embeddings of two to four numbers, so you can
check every step by hand. The one piece the earlier lessons skipped is how the model knows
**word order**.

## The parts, in order

1. **Word embedding.** Each token is mapped to a short vector by learned weights.
2. **Positional encoding.** A position-specific vector is added to each embedding.
3. **Masked self-attention.** Each token blends the values of itself and earlier tokens
   (→ query-key-value-attention).
4. **Residual connection.** The attention output is added to its input.
5. **Output layer.** A fully connected layer and softmax give a probability for every token
   in the vocabulary. (The original GPT reused the embedding weights in reverse instead.)

The toy model uses one attention cell; the original GPT stacked 12, and real models also put a
feed-forward layer after each attention step (→ mlp-layers-store-facts). Every position
predicts the word after it, which is how the model is checked against the known text in
training.

## Why position must be added

Attention is a weighted sum over the tokens a word can see. Sums don't care about order, so
without help "Squatch eats pizza" and "pizza eats Squatch" would give "Squatch" exactly the same
mix. Positional encoding fixes this by adding a different pattern to each position, built from
sine and cosine waves of different frequencies:

`PE(pos, 2i) = sin(pos / 10000^(2i/d))` and `PE(pos, 2i+1) = cos(pos / 10000^(2i/d))`

Low dimensions use fast waves that change at every position; high dimensions use slow waves
that tell far-apart positions apart.

## Worked example: the same word at two positions

Take d = 4 and the word "the" with embedding [0.5, 0.5, 0.5, 0.5].

| position | sin(p) | cos(p) | sin(p/100) | cos(p/100) |
|---|---|---|---|---|
| 0 | 0.000 | 1.000 | 0.000 | 1.000 |
| 1 | 0.841 | 0.540 | 0.010 | 1.000 |
| 2 | 0.909 | −0.416 | 0.020 | 1.000 |

(For d = 4 the second pair divides by 10000^(2/4) = 100.)

- "the" at position 0: [0.5, 0.5, 0.5, 0.5] + [0, 1, 0, 1] = **[0.5, 1.5, 0.5, 1.5]**
- "the" at position 2: [0.5, 0.5, 0.5, 0.5] + [0.909, −0.416, 0.020, 1.000] =
  **[1.409, 0.084, 0.520, 1.500]**

Same word, two different vectors, so attention can now treat them differently.

## How the reply is generated

The prompt is processed with the mask, then an end-of-sequence token is appended. The output
layer at that position predicts the first word of the reply. That word is appended and fed
back in, the next word is predicted, and so on until the model outputs the end token or a
length limit stops it. Prompt and reply live in one sequence, which is why they share the
context limit.

## Common mistakes

- **Thinking attention knows order on its own.** It doesn't; position is added.
- **Assuming the prompt is read unmasked.** In a decoder-only model the same masked layers read
  both prompt and reply.
- **Treating the reply as a separate output.** Every reply token becomes input for the next,
  and attends back to the prompt, which is how a "Don't" at the start isn't lost.

## Where you'll see it in AI

Context limits that count prompt plus reply, stop reasons in API responses, and positional
schemes in current open models (rotary embeddings, linked below as extra viewing). You'll
build the same stack in code in → build-gpt-from-scratch.
