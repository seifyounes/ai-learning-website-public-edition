task: |
  Train the counting version on the real dataset, see infinite loss appear and disappear, and
  confirm that softmax of the log-counts gives the same probabilities. Python 3 only; the script
  downloads the names file (about 228 KB) from the lecture's GitHub repository.

  ```python
  import math, urllib.request

  URL = "https://raw.githubusercontent.com/karpathy/makemore/master/names.txt"
  names = urllib.request.urlopen(URL).read().decode().split()
  SMOOTH = 1                                   # fake count added to every pair

  chars = "." + "abcdefghijklmnopqrstuvwxyz"   # "." marks the start and end of a name
  idx = {ch: i for i, ch in enumerate(chars)}
  counts = [[SMOOTH] * 27 for _ in range(27)]
  for name in names:
      seq = "." + name + "."
      for a, b in zip(seq, seq[1:]):
          counts[idx[a]][idx[b]] += 1
  probs = [[c / sum(row) for c in row] for row in counts]

  def avg_nll(words):
      pairs = [(a, b) for w in words for a, b in zip("." + w + ".", w + ".")]
      p = [probs[idx[a]][idx[b]] for a, b in pairs]
      return float("inf") if 0 in p else -sum(math.log(x) for x in p) / len(p)

  print("names:", len(names), " uniform loss:", round(math.log(27), 3))
  print("training loss:", round(avg_nll(names), 3))
  print("'andrej', 'andrejq':", round(avg_nll(["andrej"]), 3), round(avg_nll(["andrejq"]), 3))

  # The network view: logits are a row of W = log(counts), and softmax gives that row back.
  W = [[math.log(c) if c else -math.inf for c in row] for row in counts]
  exps = [math.exp(z) for z in W[idx["a"]]]
  softmax = [e / sum(exps) for e in exps]
  print("softmax matches counting:",
        all(abs(s - p) < 1e-12 for s, p in zip(softmax, probs[idx["a"]])))
  ```

A language model does one thing: given what came before, it assigns a probability to every
possible next token. This lecture builds the smallest real example, a model that predicts the
next character of a name from the previous one, and introduces the loss every LLM is trained
on: **the average negative log-likelihood** of the true next token.

## Two ways to build the same model

**By counting.** Pad each name with a "." at both ends, count every pair of neighbouring
characters into a 27 × 27 table, and divide each row by its total. Row "a" now holds the
probability of each character following "a". Sampling from rows one character at a time
generates new names.

**As a network.** Turn the previous character into a one-hot vector of length 27, multiply by
a 27 × 27 weight matrix W to get 27 **logits**, exponentiate them, and divide by their sum. That
last step, the **softmax**, turns any 27 numbers into probabilities. Train W with the loop from
the micrograd lesson (→ micrograd-from-scratch): forward, loss, backward, update.

Both routes reach a training loss of about 2.45. They are the same model: multiplying a one-hot
vector by W just picks out one row of W, so the trained W is the log of the count table.

## Worked example: scoring predictions

**The loss.** For each true next character, take the probability the model gave it, take the
log, flip the sign, and average. Suppose a model scores the name "ava" (pairs .a, av, va, a.)
with probabilities 0.14, 0.02, 0.25 and 0.20:

- logs: −1.97, −3.91, −1.39, −1.61; sum −8.87
- average negative log-likelihood: 8.87 ÷ 4 ≈ **2.22**

The rare pair "av" contributes most. If any pair had probability 0, its log would be minus
infinity and the loss would be infinite, which is why the lecture adds fake counts (smoothing).

**The baselines.** A model that knows nothing gives each character 1/27, a loss of ln 27 ≈
**3.30**. The bigram model's 2.45 is better. e^2.45 ≈ **11.6** is its perplexity: on average
it's about as unsure as choosing among 11–12 equally likely characters, instead of 27.

**Softmax on numbers.** Logits (2.0, 1.0, −1.0) exponentiate to (7.39, 2.72, 0.37), which sum
to 10.48, giving probabilities (0.71, 0.26, 0.04). If the true character is the second one, its
loss is −ln 0.26 ≈ 1.35.

## Smoothing and regularization

Fake counts make the table's predictions more uniform; more counts, flatter predictions. The
network has a matching knob: add a penalty such as 0.01 × mean(W²) to the loss. Zero weights
mean a uniform softmax, so the penalty pulls predictions towards uniform, and its strength
plays the same role as the number of fake counts.

The table can't grow: with 10 previous characters, the number of combinations explodes. The
network version can, by changing only the forward pass. That's the path the rest of the series
takes, up to a transformer.

## Common mistakes

- **Reading the loss without a baseline.** Compare with ln(vocabulary size) for a uniform guess.
- **Expecting a loss of 0.** On real held-out data it would mean perfect prediction; suspect a
  leak between training and validation data instead.
- **Treating probability 0 as harmless.** One zero makes the loss infinite and can break
  sampling; smooth or regularize.

## Where you'll see it in AI

- **Every LLM's training loss** is this average negative log-likelihood, computed over
  next-token predictions with a vocabulary of tens of thousands of tokens
  (→ transformers-attention).
- **Embedding tables:** one-hot × W as a row lookup is exactly how models turn token IDs into
  vectors (→ embeddings-vector-databases).
- **Temperature and sampling** reshape the softmax before drawing the next token, which is why
  the same prompt can give different answers (→ calling-an-llm-api).
