task: |
  Run backpropagation's bookkeeping by hand for two examples, then check it in Python. The
  numbers ignore the activation's slope, so they show the proportions, not exact gradients.

  The previous layer has two neurons; the output layer has a "2" neuron and an "8" neuron.
  Weights into "2": (0.5, −1.0). Weights into "8": (0.3, 0.7).

  1. Example A (an image of a 2) is worked in the lesson. Example B is an image of an 8: the
     previous layer's activations are (0.2, 0.8), the outputs are "2" = 0.5 and "8" = 0.4.
  2. For B, write the wanted change for each output, the four weight nudges (wanted change ×
     incoming activation), and the wished change for each previous neuron (sum of weight ×
     wanted change).
  3. Average A's and B's weight nudges. Which two weights' nudges changed sign once B was
     included, and why?

  ```python
  import numpy as np

  W = np.array([[0.5, -1.0],    # weights into the "2" neuron
                [0.3,  0.7]])   # weights into the "8" neuron
  examples = [  # (previous activations, outputs now, targets)
      (np.array([0.9, 0.1]), np.array([0.2, 0.6]), np.array([1, 0])),  # A: a 2
      (np.array([0.2, 0.8]), np.array([0.5, 0.4]), np.array([0, 1])),  # B: an 8
  ]
  weight_nudges = []
  for a_prev, out, target in examples:
      want = target - out
      weight_nudges.append(np.outer(want, a_prev))
      print("wishes for previous layer:", W.T @ want)
  print("average weight nudges:\n", np.mean(weight_nudges, axis=0))
  ```

  Success: your hand values for B match the printout (previous-layer wishes −0.07 and 0.92),
  and you can name the two weights whose nudges flipped sign after averaging.

A network learns by adjusting its weights and biases to lower a cost. **Backpropagation** is
how it works out which way, and by how much, to adjust each of them. Every model you'll use was
trained this way, and the idea fits in one sentence: start from the output's error, and pass
each layer's "wishes" back to the layer before it.

## What the gradient is telling you

The gradient has one component per weight and bias. Rather than picturing a direction in 13,000
dimensions, read each component as a **sensitivity**. If weight A's component is 3.2 and weight
B's is 0.1, a small change to A moves the cost about 32 times as much as the same change to B.
Backprop's job is to compute all of these at once.

## Worked example: one image of a 2

Take two neurons in the second-to-last layer, with activations (0.9, 0.1), and two output
neurons, "2" and "8". Weights into "2" are (0.5, −1.0); weights into "8" are (0.3, 0.7). The
network currently outputs "2" = 0.2 and "8" = 0.6. These numbers show proportions; real backprop
also multiplies by the activation function's slope.

1. **Wanted changes at the output:** "2" should rise by 1 − 0.2 = **+0.8**; "8" should fall by
   0 − 0.6 = **−0.6**. Bigger errors get bigger nudges.
2. **Weight nudges into "2"** are the wanted change times each incoming activation: 0.8 × 0.9 =
   **0.72** and 0.8 × 0.1 = **0.08**. The weight from the bright neuron moves nine times more.
3. **Wishes for the previous layer** add up every output's request, scaled by the weights:
   - neuron 1: 0.5 × 0.8 + 0.3 × (−0.6) = **+0.22**
   - neuron 2: −1.0 × 0.8 + 0.7 × (−0.6) = **−1.22**

Neuron 2 should get much dimmer: both outputs agree on that. Those wishes become the targets for
the layer before, and the same three steps repeat backwards to the input. That is the
"propagation" in backpropagation.

## From one example to a training step

One example's wishes are one-sided: follow only images of 2s and the network learns to answer
"2" for everything. So you compute the nudges for many examples and **average** them. The
average is proportional to the negative gradient, and taking a step along it is one step of
gradient descent (→ calculus-for-optimization).

Averaging over the whole dataset for every step is slow. The usual shortcut: shuffle the data,
split it into **mini-batches** of around 100 examples, and take a step per mini-batch. MNIST's
60,000 training images give 600 steps per pass instead of one. Each step is noisier, but there
are far more of them. This is **stochastic gradient descent**.

## Common mistakes

- **Thinking backprop is the learning rule.** Backprop computes the gradient; gradient descent
  (or a variant like Adam) uses it to update the weights.
- **Expecting a smooth loss curve with mini-batches.** Some zigzag is normal.
- **Forgetting the data.** All of this averages what labelled examples ask for. Without enough
  of them, there's nothing good to average.

## Where you'll see it in AI

- **Training and fine-tuning LLMs** runs exactly this loop on mini-batches of text: forward
  pass, loss, backprop, update (→ fine-tuning-fundamentals).
- **Training memory:** backprop needs a gradient for every trainable weight plus the saved
  activations, which is why training needs far more memory than running a model
  (→ micrograd-from-scratch builds the machinery).
- **The calculus behind the nudges** is the chain rule, applied layer by layer
  (→ backprop-chain-rule-calculus, the next lesson).
