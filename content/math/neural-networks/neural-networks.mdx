task: |
  Count a network's parameters, then turn the count into a memory table for your own machine.
  A spreadsheet works; so does this Python script.

  1. By hand, count the weights and biases of the video's 784 → 16 → 16 → 10 network. Each layer
     has (inputs × outputs) weights plus one bias per output.
  2. Run the script with your machine's memory (GPU memory, or unified memory on a Mac).
  3. Mark the largest model your machine can run, and at which precision.

  ```python
  def count_params(sizes):
      return sum(n_in * n_out + n_out for n_in, n_out in zip(sizes, sizes[1:]))

  print("digit network:", count_params([784, 16, 16, 10]))

  memory_gb = 16          # change to your machine's memory
  headroom_gb = 2         # rough room for the context
  for name, billions in [("3B", 3), ("7B", 7), ("8B", 8), ("70B", 70)]:
      for label, bytes_per_param in [("fp16", 2), ("8-bit", 1), ("4-bit", 0.5)]:
          gb = billions * bytes_per_param
          verdict = "fits" if gb + headroom_gb <= memory_gb else "too big"
          print(f"{name:>4} {label:>6}: {gb:5.1f} GB  {verdict}")
  ```

Strip the mystique: a neural network is **a function with a very large number of adjustable
numbers in it**. Each layer takes a weighted sum of the previous layer, adds a bias, and bends the
result through a simple function. Training means finding values for all those numbers. That's
the whole picture this track builds on, and it already answers practical questions: the number
of parameters decides how much memory a model needs and how much each answer costs.

## Neurons, weights and biases

In the lecture's digit recognizer, a **neuron** is something that holds a number, its
activation. The input layer has 784 neurons, one per pixel of a 28 × 28 image; the output layer
has 10, one per digit; two hidden layers of 16 sit between.

Each neuron in a layer is connected to every neuron in the layer before, and each connection
has a **weight**. The neuron computes the weighted sum of the previous layer's activations, adds
its own **bias**, and squishes the total into the range 0–1. The weights decide which pattern
the neuron responds to; the bias decides how strong the evidence must be before it switches on.
Written for a whole layer at once, that's σ(W·a + b): one matrix product, one added vector, one
squish (→ layer-forward-pass works through it with numbers).

## Worked example: counting the knobs, then sizing a real model

**Count the digit network.** Each layer has (inputs × outputs) weights plus one bias per output:

1. 784 → 16: 784 × 16 + 16 = 12,560
2. 16 → 16: 16 × 16 + 16 = 272
3. 16 → 10: 16 × 10 + 10 = 170

Total: **13,002** parameters. Stored as 4-byte numbers, that's about 52 KB.

**Scale up.** A language model with 8 billion parameters runs the same arithmetic, so its
memory is just parameters × bytes per parameter. On a laptop with a 16 GB GPU:

1. **fp16 (2 bytes):** 8B × 2 = 16 GB. It doesn't fit: nothing is left for the context.
2. **8-bit (1 byte):** 8B × 1 = 8 GB. Fits, with room for a decent context.
3. **4-bit (0.5 bytes):** 8B × 0.5 = 4 GB (real files run a little larger). Fits easily, at a
   small quality cost you should test on your own tasks.

Pick 8-bit if quality matters most, 4-bit if you want long contexts or a second model loaded.
Quantization means fewer bytes per parameter, and it's the trick that put capable models on
laptops (→ local-open-models).

## The hope behind the layers

The lecture's motivation for layers: maybe the first hidden layer spots small edges, the next
combines edges into loops and lines, and the output combines those into digits. Speech and
language break down the same way, from sounds to syllables to words. That's a hope about what
training might find, not a guarantee; a later lesson looks at why this kind of hierarchy
helps (→ why-deep-networks).

The squish matters too. Early networks used the sigmoid; most modern ones use ReLU, max(0, z),
because deep networks train much more easily with it (→ choosing-activation-functions).

## Common mistakes

- **Reading "7B" as knowledge.** It counts parameters, which tells you memory and cost, not
  what the model knows.
- **Forgetting the context's memory.** A model that exactly fills your GPU will fail or crawl
  on long prompts; leave headroom.
- **A local model that loads but runs painfully slowly** usually didn't fit in GPU memory and
  spilled into system RAM. Pick a smaller quantization or a smaller model.
- **Assuming each neuron has a clear meaning.** Some do; many respond to mixtures of patterns.

## Where you'll see it in AI

- **Model sizes and prices:** every "B" in a model name is this parameter count, and bigger
  counts mean more compute per token (→ models-and-effort).
- **Running models locally:** the sizing multiply above is the first step of every local setup
  (→ local-open-models).
- **Transformers:** each block contains layers of exactly this form, plus attention
  (→ transformers-attention).
