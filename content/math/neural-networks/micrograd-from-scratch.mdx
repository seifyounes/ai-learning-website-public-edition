task: |
  Build a micrograd-style engine, check its gradients, and reproduce both bugs from the
  lecture. You need Python 3 and nothing else.

  ```python
  import math

  class Value:
      def __init__(self, data, children=()):
          self.data, self.grad = data, 0.0
          self._prev, self._backward = children, lambda: None

      def __add__(self, other):
          out = Value(self.data + other.data, (self, other))
          def _backward():
              self.grad += out.grad
              other.grad += out.grad
          out._backward = _backward
          return out

      def __mul__(self, other):
          out = Value(self.data * other.data, (self, other))
          def _backward():
              self.grad += other.data * out.grad
              other.grad += self.data * out.grad
          out._backward = _backward
          return out

      def tanh(self):
          t = math.tanh(self.data)
          out = Value(t, (self,))
          def _backward():
              self.grad += (1 - t * t) * out.grad
          out._backward = _backward
          return out

      def backward(self):
          order, seen = [], set()
          def visit(v):
              if v not in seen:
                  seen.add(v)
                  for child in v._prev:
                      visit(child)
                  order.append(v)
          visit(self)
          self.grad = 1.0
          for v in reversed(order):
              v._backward()

  a, b, c, f = Value(3.0), Value(-2.0), Value(4.0), Value(-1.0)
  L = (a * b + c) * f
  L.backward()
  print(L.data, a.grad, b.grad, c.grad, f.grad)
  ```

Backpropagation sounds like an advanced algorithm, but its core is small enough to write in an
afternoon. This lecture builds **micrograd**, an engine that computes gradients for any
expression built from a few operations, and then uses it to train a small network. Once you've
seen it, the training loop behind every model you use, from a classifier to an LLM, follows the
same four steps: forward pass, loss, backward pass, update.

## Expressions that remember how they were made

Each number is wrapped in a Value that stores its data, its gradient (starting at 0), the
values it was made from, and how to pass a gradient back to them. Adding or multiplying Values
builds a graph as you compute. A network's output, or its loss, is just the last node of a very
large graph of this kind.

Backprop then walks that graph from the end. The output's gradient is 1. Each node applies the
**chain rule**: multiply the gradient arriving from above by the node's local derivative.

- A **plus** node passes the incoming gradient to each input unchanged.
- A **times** node passes to each input the incoming gradient times the *other* input's value.
- A **tanh** node multiplies by 1 − tanh², using its own output.

## Worked example: gradients on a small expression

Let a = 3, b = −2, c = 4, f = −1, and compute L = (a × b + c) × f.

1. **Forward:** e = a × b = −6; d = e + c = −2; L = d × f = **2**.
2. **Backward from L:** L's gradient is 1. L is a times node, so dL/dd = f = −1 and
   dL/df = d = −2.
3. **Through the plus:** d passes its −1 straight through, so dL/de = −1 and dL/dc = −1.
4. **Through the times:** dL/da = b × (−1) = **2** and dL/db = a × (−1) = **−3**.

**Check numerically.** Nudge a to 3.001: e = −6.002, d = −2.002, L = 2.002. The change
0.002 ÷ 0.001 = 2, matching dL/da. **Take a step.** Move every input against its gradient with
step size 0.01: a = 2.98, b = −1.97, c = 4.01, f = −0.98. Recompute and L ≈ 1.82, down from 2.
That's one step of gradient descent, the same move that trains a network's weights.

## From expression to training loop

A neuron is tanh(w·x + b), a layer is a list of neurons, and a network is a list of layers. The
lecture's network takes 3 inputs, has two hidden layers of 4 and one output: 41 parameters. With
four training examples and a squared-error loss, training is a loop:

1. **Forward:** run every example and compute the loss.
2. **Zero the gradients**, then **backward** from the loss.
3. **Update:** move every parameter a small step against its gradient.

The step size is the learning rate. Too small and progress crawls; too large and the loss jumps
around or blows up.

## Common mistakes

- **Overwriting instead of adding gradients.** A value used twice gets gradient from both uses;
  `=` keeps only one of them.
- **Forgetting to zero the gradients.** They pile up across steps. The lecture's own toy run
  still converged with this bug, which is exactly why it's easy to miss.
- **Trusting a gradient you haven't checked.** Compare against a numerical nudge or against
  PyTorch whenever you add an operation.

## Where you'll see it in AI

- **PyTorch and other frameworks** do exactly this, with tensors instead of single numbers so
  the work runs in parallel. `loss.backward()` and `optimizer.zero_grad()` are the same steps.
- **Training memory:** every trainable parameter needs a gradient as large as itself, and
  optimizers such as Adam keep about two more numbers per parameter. That is why fine-tuning
  needs several times the memory of running a model, and why LoRA trains only small adapters
  (→ fine-tuning-fundamentals).
- **Language models** train with the same loop on next-token prediction, with a cross-entropy
  loss instead of squared error (→ makemore-bigram-model).
