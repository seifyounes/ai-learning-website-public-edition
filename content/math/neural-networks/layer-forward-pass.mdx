  Run a two-layer forward pass by hand, then confirm it in a few lines of NumPy.

  1. Use x = (1, 2); W1 with rows (1, −1) and (0.5, 0.5); b1 = (0, 1); ReLU in the hidden layer.
  2. Use W2 = (1, 2), b2 = −3 and a sigmoid at the output.
  3. Write the shape of W1, b1, W2 and b2 before computing anything, then compute z1, a1, z2
     and the output.
  4. Count the parameters (all weights plus all biases).

  ```python
  import numpy as np

  x  = np.array([1.0, 2.0])
  W1 = np.array([[1.0, -1.0], [0.5, 0.5]]); b1 = np.array([0.0, 1.0])
  W2 = np.array([[1.0, 2.0]]);              b2 = np.array([-3.0])

  z1 = W1 @ x + b1
  a1 = np.maximum(0, z1)
  z2 = W2 @ a1 + b2
  out = 1 / (1 + np.exp(-z2))
  print(z1, a1, z2, out)
  print("params:", W1.size + b1.size + W2.size + b2.size)
  ```

A layer of a neural network is one line of algebra: **z = W·x + b, then a = g(z)**. Every
model you'll use, including each block inside an LLM, is built from this line repeated many
times. Being able to run it by hand, and to say the shape of every piece, is what turns model
diagrams and framework code from symbols into something you can check.

## From one unit to one layer

A single unit takes the input vector x, computes a weighted sum wᵀx plus a bias b, and passes
the result z through an activation such as the sigmoid. That's logistic regression, done once.

A hidden layer is several of these units side by side, each with its own weight vector. Write
each unit's weights as one **row** of a matrix W, and the separate dot products become a single
matrix-vector product. With 3 inputs and 4 units:

- W[1] is **4 × 3** (one row per unit, one column per input), b[1] is 4 × 1.
- z[1] = W[1]·x + b[1], and a[1] = g(z[1]) applies the activation to each entry.
- The output layer does the same with a[1] as its input: W[2] is 1 × 4, b[2] is a single number.

The rule to remember: **W[l] has shape (units in layer l) × (units in layer l − 1).** If you
call the input a[0], every layer is the same two lines.

## Worked example: a two-layer forward pass

Input x = (1, 2). Hidden layer: W1 has rows (1, −1) and (0.5, 0.5), b1 = (0, 1), ReLU. Output
layer: W2 = (1, 2), b2 = −3, sigmoid.

1. **Multiply:** W1·x = (1×1 + (−1)×2, 0.5×1 + 0.5×2) = (−1, 1.5).
2. **Add the bias:** z1 = (−1, 1.5) + (0, 1) = (−1, 2.5).
3. **Activate:** a1 = ReLU(z1) = (0, 2.5).
4. **Output layer:** z2 = 1×0 + 2×2.5 − 3 = 2.
5. **Sigmoid:** 1 / (1 + e^(−2)) ≈ **0.88**, read as an 88% probability of the positive class.

Parameter count: W1 has 4 weights, b1 has 2, W2 has 2, b2 has 1, so 9 in total. A real model
runs the same steps with matrices thousands of rows wide.

## Parameters learn; activations flow

Keep two kinds of numbers apart. **Parameters** (W and b) are learned in training and stay fixed
while the model answers. **Activations** (z and a) are computed fresh for each input and exist
only during the pass. Memory for parameters depends on model size; memory for activations also
depends on how much input you send. In a transformer, the cached keys and values for earlier
tokens are activation-side, which is why long prompts need more memory (→ kv-cache-inference).

## Common mistakes

- **Transposed weights.** Building W as (inputs × units) and then wondering why W·x fails.
  Write the shapes down before the numbers.
- **Mixing up z and a.** z is before the activation; a is after. The next layer reads a.
- **Forgetting the bias in a parameter count.** It's small per layer but it is part of the model.

## Where you'll see it in AI

- **Every generated token** is one forward pass through every layer, so a model with bigger
  matrices costs more time and money per token. Model tiers are, in large part, layer sizes
  (→ models-and-effort).
- **Embeddings** are the activations of a chosen layer, saved and reused (→
  embeddings-vector-databases).
- **Attention** computes its queries, keys and values with exactly this kind of layer, one matrix
  each (→ transformers-attention).
