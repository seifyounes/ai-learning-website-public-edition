task: |
  Build gradient boosting from scratch in about 25 lines of NumPy and watch the learning rate
  and the number of trees trade off. Each "tree" here is a stump (one split) to keep it short.
  Run it in a free Google Colab notebook:

  ```python
  import numpy as np

  rng = np.random.default_rng(0)
  x = rng.uniform(0, 10, 200)
  y = 20 + 3 * x + 8 * np.sin(x) + rng.normal(0, 3, 200)   # a wiggly truth plus noise
  x_tr, y_tr, x_te, y_te = x[:150], y[:150], x[150:], y[150:]

  def fit_stump(x, r):
      """Best single split of x for predicting residuals r: (threshold, left value, right value)."""
      best = None
      for t in np.unique(x)[1:]:
          left, right = r[x < t], r[x >= t]
          sse = ((left - left.mean()) ** 2).sum() + ((right - right.mean()) ** 2).sum()
          if best is None or sse < best[0]:
              best = (sse, t, left.mean(), right.mean())
      return best[1:]

  def boost(learning_rate, n_trees):
      start = y_tr.mean()                       # step 1: predict the average
      pred_tr, pred_te = np.full(150, start), np.full(50, start)
      for i in range(1, n_trees + 1):
          t, lv, rv = fit_stump(x_tr, y_tr - pred_tr)   # a tree on the residuals
          pred_tr += learning_rate * np.where(x_tr < t, lv, rv)
          pred_te += learning_rate * np.where(x_te < t, lv, rv)
          if i in (1, 10, 50, 200, 1000):
              print(f"  {i:>4} trees: train {np.mean((pred_tr - y_tr) ** 2):6.1f}  "
                    f"test {np.mean((pred_te - y_te) ** 2):6.1f}")

  for lr in (1.0, 0.1):
      print("learning rate", lr)
      boost(lr, 1000)
  ```

A random forest grows many trees independently and averages them. **Gradient boosting grows
small trees one after another, each trained on what the model so far still gets wrong, and adds
each one in at a small, scaled-down step.** It's the gradient descent loop from earlier in this
track, with trees as the steps, and it's the usual first choice for predictions from tables.

## The loop

1. **Start** with one prediction for everyone: the average of the target.
2. **Compute residuals:** real value minus current prediction for each row.
3. **Fit a small tree** (often 8 to 32 leaves) to predict those residuals. Each leaf's value is
   the average residual of the rows in it.
4. **Add the tree, scaled** by a learning rate such as 0.1.
5. **Repeat** from step 2 until you hit the tree limit or validation error stops improving.

The prediction for a new case is the average plus every tree's scaled output.

## Worked example: delivery times

Four orders took 30, 50, 40 and 80 minutes. Orders 1 and 3 were short-distance; 2 and 4 long.

- **Start:** predict the average, **50**, for all. Residuals: −20, 0, −10, +30. Sum of squared
  residuals: 400 + 0 + 100 + 900 = **1,400**.
- **Tree 1** splits on distance. Short leaf: average of −20 and −10 = **−15**. Long leaf:
  average of 0 and 30 = **+15**.
- **Add it at learning rate 0.1:** short orders 50 − 1.5 = **48.5**; long orders
  50 + 1.5 = **51.5**.
- **New residuals:** −18.5, −1.5, −8.5, +28.5. Sum of squares: 342.25 + 2.25 + 72.25 + 812.25
  = **1,229**, down from 1,400.

At learning rate 1.0 the same tree would jump straight to 35 and 65. On four rows that looks
better; on real data, committing fully to each tree's guess means also committing to its noise.
Many small steps, each corrected by the next tree, generalize better.

## Classical ML or a foundation model?

- **Structured data** (columns of numbers and categories): logistic regression as the baseline,
  then gradient-boosted trees or a random forest. Cheap, fast, inspectable.
- **Unstructured data** (language, images, audio): foundation models, called through an API or
  fine-tuned. Training them from scratch is a lab's job.
- **Mixed:** often both. An LLM turns text into a few columns or an embedding, and a tree makes
  the prediction.

## Common mistakes

- **High learning rate, many trees.** Fast overfitting. Lower the rate and add trees.
- **Choosing the number of trees by training error.** It always falls; use validation error and
  stop early.
- **Deep trees.** Boosting works with small trees; deep ones fit noise in the residuals.
- **Skipping the baseline.** A boosted tree still has to beat logistic regression and the
  majority class (→ machine-learning-fundamentals).

## Where you'll see it in AI

- **Production tabular models** (risk, pricing, churn, ranking features) are very often boosted
  trees, in libraries such as XGBoost, LightGBM and CatBoost.
- **Gradient descent, again.** Each tree is a step down the loss, like the parameter updates in
  → fitting-by-gradient-descent and the training of → neural-networks.
- **Evaluating the result** uses the tools in → evaluation-metrics, and the routing above
  decides when an LLM is worth its cost.
