applyIt: |
  **Whenever a decision rests on a small labeled set, check that the winner wins on every
  slice, not just one.** That holds for choosing between two models, two feature sets or two
  settings. Take a comparison you've made (or are about to make) in your own work and run it
  across folds.

  1. Split your labeled examples into 5 groups. If rows belong to the same customer, user,
     patient or document, keep each one's rows in a single group.
  2. For each group: build or tune on the other four, score on this one. Write down all five
     scores for each option.
  3. Compare the averages *and* the spread. If the gap between options is smaller than the
     fold-to-fold swing, call it a tie and pick the cheaper option.

  **If you build software:** scikit-learn's `cross_val_score` does steps 1–2 in one line, and
  `GroupKFold` or `TimeSeriesSplit` handle shared customers and dates. **If you don't code:**
  five filtered copies of a spreadsheet tab do the same job by hand for a formula-based rule.
  Success: you have five scores per option and a decision that survives the spread.

task: |
  See how much a single split can mislead, then fix it with folds. Run this in a free Google
  Colab notebook (scikit-learn is preinstalled). It uses a small built-in medical dataset of 569
  tumour measurements labelled benign or malignant.

  ```python
  from sklearn.datasets import load_breast_cancer
  from sklearn.model_selection import train_test_split, cross_val_score
  from sklearn.linear_model import LogisticRegression
  from sklearn.neighbors import KNeighborsClassifier
  from sklearn.tree import DecisionTreeClassifier
  from sklearn.pipeline import make_pipeline
  from sklearn.preprocessing import StandardScaler

  X, y = load_breast_cancer(return_X_y=True)

  # 1. One model, five different single splits
  for seed in range(5):
      X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.25, random_state=seed)
      tree = DecisionTreeClassifier(random_state=0).fit(X_tr, y_tr)
      print("split", seed, "accuracy", round(tree.score(X_te, y_te), 3))

  # 2. Three methods, compared with 10-fold cross-validation
  models = {
      "logistic regression": make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000)),
      "nearest neighbours": make_pipeline(StandardScaler(), KNeighborsClassifier()),
      "decision tree": DecisionTreeClassifier(random_state=0),
  }
  for name, model in models.items():
      s = cross_val_score(model, X, y, cv=10)
      print(f"{name}: mean {s.mean():.3f}  min {s.min():.3f}  max {s.max():.3f}")
  ```

  1. From part 1, write down the lowest and highest single-split accuracy for the same tree.
  2. From part 2, rank the three methods by mean. Is the gap between first and second bigger
     than the min-to-max swing of either one?
  3. Change `cv=10` to `cv=4` and rerun. Does the ranking hold?

A single train/test split is one roll of the dice: a different 25% held out gives a different
score, sometimes a very different one. **Cross-validation removes the luck by giving every part
of the data a turn as the test set and averaging the results.** It's how you compare methods
and pick settings when labeled data is scarce, which in applied AI is most of the time.

## How k-fold works

Cut the data into *k* equal blocks (folds). For each fold: train on the other *k − 1*, test on
this one, write down the score. You end with *k* scores per method. Their **mean** estimates how
the method does on new data; their **spread** tells you how much to trust the mean.

- **k = 10** is the common default: each model trains on 90% of the data.
- **Leave-one-out** makes every row its own fold: as much training data as possible, but one
  model per row, so it's slow on anything large.
- Smaller *k* is cheaper but trains on less data each time, so scores run a little low.

## Worked example: when one split picks the wrong winner

Two methods, 4-fold cross-validation, accuracy per fold:

| Fold | Method A | Method B |
|---|---|---|
| 1 | 0.90 | 0.82 |
| 2 | 0.70 | 0.80 |
| 3 | 0.85 | 0.84 |
| 4 | 0.75 | 0.78 |
| Mean | 0.80 | 0.81 |

Had you split once and the test block happened to be fold 1, A would win by 8 points. Across all
four folds the means are within a point, and A swings 20 points between folds while B stays
within 6. The honest conclusion: no real difference in accuracy, and B is the more predictable
choice.

## Tuning a setting

Many methods have a knob you choose rather than learn: the penalty strength in
→ ridge-regularization, the depth of a tree, the number of neighbours. Try a range of values,
cross-validate each, keep the best, then **retrain once on all the training data** with that
value. If you have the data for it, keep a separate test set that took no part in any of this
and score it once at the end; the tuning folds have been looked at too often to be neutral.

## Common mistakes

- **Leaky folds.** Rows from the same customer, patient or document in different folds let the
  model recognise them. Group the folds.
- **Random folds on time series.** Train on the past and test on the period after.
- **Preprocessing before splitting.** Scaling or selecting features on the full dataset lets
  test rows shape the training. Do it inside each fold (a scikit-learn pipeline does this).
- **Reading only the mean.** A gap between methods smaller than the fold-to-fold spread is
  noise.

## Where you'll see it in AI

- **Small labeled sets** are the norm when you build a classifier on top of embeddings
  (→ embeddings-vector-databases) or fine-tune a small model: cross-validation tells you
  whether the result is real before you spend more on labels.
- **Choosing prompts or settings on an eval set** has the same trap as tuning on folds: the
  version you picked looks better than it is. Keep a held-out set (→ evals-and-testing).
- **With very large datasets**, a single held-out slice of a few percent already holds
  thousands of examples, so k-fold matters less; that's the regime the optional
  train/dev/test lecture below describes.
