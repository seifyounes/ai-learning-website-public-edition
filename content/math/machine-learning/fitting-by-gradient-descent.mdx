task: |
  Run gradient descent yourself and watch the learning rate decide everything. Use the three
  points from the lecture (weight → height) in a free Google Colab notebook or any Python:

  ```python
  weights = [0.5, 2.3, 2.9]
  heights = [1.4, 1.9, 3.2]

  def gradient(intercept, slope):
      d_int = d_slope = 0.0
      for x, y in zip(weights, heights):
          residual = y - (intercept + slope * x)
          d_int += -2 * residual
          d_slope += -2 * x * residual
      return d_int, d_slope

  def descend(learning_rate, steps=1000):
      intercept, slope = 0.0, 1.0
      for step in range(steps):
          d_int, d_slope = gradient(intercept, slope)
          step_int, step_slope = learning_rate * d_int, learning_rate * d_slope
          intercept, slope = intercept - step_int, slope - step_slope
          if max(abs(step_int), abs(step_slope)) < 0.0001:
              break
      return step + 1, round(intercept, 2), round(slope, 2)

  for lr in [0.01, 0.05, 0.1]:
      print("learning rate", lr, "-> steps, intercept, slope:", descend(lr))
  ```

  1. Record steps, intercept and slope for each learning rate. Compare with the least squares
     answer, `numpy.polyfit(weights, heights, 1)` (it lists the slope first).
  2. One rate should need several times more steps than another, and one should blow up to
     `nan`. Which, and why does a bigger step overshoot the bottom?
  3. Add `print(step, intercept, slope)` inside the loop for `0.1` and watch the first five
     steps. Do the values swing from side to side?

Least squares found the best line with a formula. Most models have no such formula: you can
write down their loss, but you can't solve for its lowest point directly. **Gradient descent
gets there by walking: compute which way is downhill, take a step proportional to how steep it
is, repeat until the steps are tiny.** The same loop, at enormous scale, trains every neural
network.

## The loop

1. Choose a loss (here, the sum of squared residuals).
2. Take its derivative with respect to each parameter. Together these are the **gradient**.
3. Start from a guess.
4. Plug the current values into the gradient.
5. **Step size = derivative × learning rate.** New value = old value − step size.
6. Go back to 4 until the step is tiny or you hit a maximum number of steps.

Because the step is proportional to the slope, it shrinks automatically as you approach the
bottom, where the slope flattens to zero.

## Worked example: rediscovering the average

Model: predict the same number *b* for everything. Data: 2, 4, 9. Loss:
SSR(b) = (2 − b)² + (4 − b)² + (9 − b)². Derivative: −2 × (15 − 3b).

**Learning rate 0.1**, start at b = 0:

| Step | b | Derivative | New b |
|---|---|---|---|
| 1 | 0 | −30 | 3 |
| 2 | 3 | −12 | 4.2 |
| 3 | 4.2 | −4.8 | 4.68 |
| 4 | 4.68 | −1.92 | 4.872 |

Each step is 40% the size of the one before, and *b* closes in on **5**, the average of the
data. That's the flat line from the previous lesson: gradient descent found the least squares
answer for the constant model without being told the formula.

**Learning rate 0.4**, same start: 0 → 12 → −4.8 → 18.72. Each step overshoots the bottom by
more than it started away, and the values run off. Nothing about the data changed; only the
step size.

## Common mistakes

- **One learning rate for every problem.** The same rate can converge on one loss and diverge
  on another, as the lecture's two-parameter example shows.
- **Stopping too early.** A loose stopping rule, or too few steps, quits before the bottom.
- **Reading only the final loss.** The curve's shape tells you whether the rate is too high,
  too low or fine.
- **Assuming the bottom is the goal.** The lowest *training* loss can be an overfit model; the
  held-out loss decides (→ bias-variance-overfitting).

## Where you'll see it in AI

- **Neural network training** is this loop with millions or billions of parameters; the
  derivatives come from backpropagation (→ neural-networks, → calculus-for-optimization).
- **Fine-tuning settings** such as learning rate, epochs and batch size are this lesson's
  knobs, exposed by hosted services (→ fine-tuning-fundamentals).
- **Mini-batches** are the stochastic gradient descent the lecture ends on: each step uses a
  random slice of the data, which is how large models train at all.
