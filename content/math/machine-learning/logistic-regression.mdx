task: |
  Score candidate S-curves by likelihood, then let gradient descent find the best one. Data:
  hours a customer used a product last week, and whether they renewed (1) or not (0).

  | Hours | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
  |---|---|---|---|---|---|---|---|---|
  | Renewed | 0 | 0 | 0 | 1 | 0 | 1 | 1 | 1 |

  ```python
  import math

  hours   = [0, 1, 2, 3, 4, 5, 6, 7]
  renewed = [0, 0, 0, 1, 0, 1, 1, 1]

  def log_likelihood(b0, b1):
      total = 0.0
      for x, y in zip(hours, renewed):
          p = 1 / (1 + math.exp(-(b0 + b1 * x)))   # probability of "renewed"
          total += math.log(p if y == 1 else 1 - p)
      return total

  for b0, b1 in [(-3.5, 1.0), (-7.0, 2.0), (-1.0, 0.5)]:
      print(f"b0={b0}, b1={b1}: log-likelihood {log_likelihood(b0, b1):.3f}")

  # Let gradient descent find the best curve (the previous lesson's loop)
  b0 = b1 = 0.0
  for step in range(5000):
      g0 = g1 = 0.0
      for x, y in zip(hours, renewed):
          p = 1 / (1 + math.exp(-(b0 + b1 * x)))
          g0 += p - y
          g1 += (p - y) * x
      b0, b1 = b0 - 0.05 * g0, b1 - 0.05 * g1
  print(f"fitted: b0={b0:.2f}, b1={b1:.2f}, log-likelihood {log_likelihood(b0, b1):.3f}")
  ```

Linear regression predicts a number. Most decisions you'll automate are yes/no: cancel or stay,
spam or not, fraud or fine. **Logistic regression squeezes a linear score through an S-shaped
curve so the output is a probability between 0 and 1, and it is fitted by making the outcomes
you actually saw as probable as possible.** That probability-plus-likelihood idea is the same
one that trains language models.

## The S-curve

Start with a score, exactly like a line: z = b0 + b1 × x (or more inputs, each with its own
weight). Then pass it through the **sigmoid**:

```text
p = 1 / (1 + e^(−z))
```

Large positive z gives p near 1; large negative z gives p near 0; z = 0 gives exactly 0.5. To
classify, choose a cut-off. 50% is the default, but the right cut-off depends on what each kind
of mistake costs.

## Maximum likelihood

There are no residuals to square, so the fit asks a different question: **if this curve were
true, how probable is the data we actually saw?** Multiply the probability the curve gave each
real outcome. In practice you add their logarithms (the **log-likelihood**), because products
of many small numbers vanish. Its negative is called **log loss** or **cross-entropy**.

## Worked example

Three customers, input = logins last month, outcome = cancelled or not.

| Logins | Outcome | Curve A: z = 2 − 0.5x | Curve B: z = 4 − x |
|---|---|---|---|
| 0 | cancelled | p(cancel) = 0.88 | p(cancel) = 0.98 |
| 4 | stayed | p(stay) = 0.50 | p(stay) = 0.50 |
| 8 | stayed | p(stay) = 0.88 | p(stay) = 0.98 |

Likelihood of A: 0.88 × 0.50 × 0.88 ≈ **0.39**. Likelihood of B: 0.98 × 0.50 × 0.98 ≈
**0.48**. B makes what happened more probable, so maximum likelihood prefers it. In log terms,
A's log loss is about 0.95 and B's about 0.73: lower is better.

Steeper isn't always better, though. When the classes overlap, a very steep curve gives the
cases on the "wrong" side of the cut-off tiny probabilities, and their log loss jumps; the task
shows this happening. That is the loss doing its job: it rewards honest probabilities, not bold
ones.

## Common mistakes

- **Treating 50% as sacred.** The cut-off is a business decision; set it from the cost of each
  error on held-out data.
- **Reading the output as certainty.** A probability is only trustworthy if the model is
  calibrated; check that cases scored around 0.8 come true about 80% of the time.
- **Skipping the baseline.** If 95% of cases are "no", a model must beat always answering "no"
  (→ machine-learning-fundamentals).
- **Keeping useless inputs.** An input whose effect is indistinguishable from zero adds cost
  and room to overfit.

## Where you'll see it in AI

- **Language models** end with a softmax, the many-class version of the sigmoid, and train on
  the same log loss over the next token (→ neural-networks, → transformers-attention).
- **Log-probabilities** returned by LLM APIs are these probabilities on a log scale, useful for
  confidence checks and classification.
- **Classifiers on embeddings** are often a logistic regression on top of the vectors
  (→ embeddings-vector-databases).
- **Metrics** such as precision, recall and ROC curves all start from choosing this lesson's
  cut-off (→ evaluation-metrics).
