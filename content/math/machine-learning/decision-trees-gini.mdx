A decision tree is a flowchart learned from data: a chain of yes/no questions ending in a
prediction. **Each question is chosen greedily, by trying every column and every cut-off and
keeping the one that leaves the purest groups.** Trees are easy to read, need no input scaling,
and are the building block of random forests and gradient boosting, which still lead on most
spreadsheet-style data.

## Measuring purity

A leaf is **pure** when every row in it has the same outcome. **Gini impurity** puts a number
on how mixed it is:

```text
Gini = 1 − (share of yes)²
         − (share of no)²
```

A pure leaf scores 0. A 50/50 leaf scores 0.5, the worst for two classes. A split's score is
the average of its two leaves, **weighted by how many rows each holds**, so a tiny pure leaf
can't win on its own.

## Worked example: escalated support tickets

Ten tickets, five of which were escalated. Starting Gini: 1 − 0.5² − 0.5² = **0.5**.

**Candidate 1, "customer on premium plan?"**

- Yes: 4 tickets, 3 escalated. Gini = 1 − 0.75² − 0.25² = **0.375**.
- No: 6 tickets, 2 escalated. Gini = 1 − (1/3)² − (2/3)² ≈ **0.444**.
- Weighted: 0.4 × 0.375 + 0.6 × 0.444 ≈ **0.417**.

**Candidate 2, "ticket mentions a refund?"**

- Yes: 5 tickets, 4 escalated. Gini = 1 − 0.8² − 0.2² = **0.32**.
- No: 5 tickets, 1 escalated. Gini = **0.32**.
- Weighted: **0.32**.

The refund question leaves purer groups, so it becomes the root. The tree then repeats the
search inside each branch, using only that branch's rows, and labels each final leaf with its
majority outcome.

For a **numeric** column such as "hours open", sort the values, try the midpoint between each
neighbouring pair as a threshold, and score each one the same way.

## Common mistakes

- **Letting the tree grow until every leaf is pure.** That's memorization. Set a maximum depth or
  a minimum leaf size, chosen by → cross-validation-folds.
- **Feeding it identifiers.** IDs, row numbers and timestamps unique to each row let a tree carve
  out one leaf per example.
- **Trusting a perfect first split.** It's often leakage.
- **Reading a deep tree as an explanation.** Depth 2–3 explains; depth 15 fits.

## Where you'll see it in AI

- **Tabular prediction** in production (churn, fraud, pricing, lead scoring) is very often tree
  ensembles built from exactly this split search (→ random-forests-bagging,
  → gradient-boosting-trees).
- **Explaining a model** to non-specialists: a shallow tree fitted to another model's
  predictions is a common way to summarise what it learned.
- **Routing in AI systems** can be a hand-written tree: which requests go to a cheap model,
  which to a strong one, which to a human. The same purity thinking helps you choose the
  questions.
