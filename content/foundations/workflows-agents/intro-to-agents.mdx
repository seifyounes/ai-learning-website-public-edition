"Agent" is the most hyped word in AI right now, so let's make it concrete. An
**automation follows steps you defined.** An **agent figures out the steps itself.**
That's the whole difference — and knowing which to use is a real skill.

## What an agent actually is

An agent is an **LLM given a goal, plus tools, plus a loop.** It thinks, takes an
action (search the web, send an email, query a database), looks at the result,
decides the next action, and repeats until the goal is met. The model is the brain;
the tools are its hands; the loop is what makes it *act* instead of just *answer*.

If you've used a research mode in ChatGPT, Gemini or Claude, or a coding agent (Claude Code,
Cursor's agent mode, Codex, GitHub Copilot's agent mode), you've already used one. You give it a
goal, and it plans, searches or reads files, uses tools, and self-corrects. Same pattern, applied
to your own work.

## A spectrum, not a switch

It helps to see three rungs rather than two boxes:

1. **Plain automation** — fixed steps, no model. Form → sheet → alert.
2. **Workflow with AI steps** — fixed steps, but one or more of them call a model to classify,
   summarise or draft (→ ai-in-automations). The *path* is still yours.
3. **Agent** — the model chooses which tool to call next, how many times, and when it's done.
   The *path* belongs to the model.

Anthropic's engineering post on building effective agents (linked below the video) draws the same
line between workflows and agents, and makes the same recommendation: start with the simplest
rung that works and climb only when you need to.

## Worked example: watching the loop run

Give an agent this goal: *"Find three venues in our city that can host a 40-person workshop on a
weekday next month, under our budget, and draft a comparison."* It has two tools: web search and
a notes file.

1. **Think:** "I need venues with capacity and pricing. Search first."
2. **Act:** search "workshop venue 40 people [city]".
3. **Observe:** ten results; two are wedding venues, one lists no prices.
4. **Think:** "Drop the wedding venues. Check the pricing page of the remaining ones."
5. **Act / observe** (several rounds): open pages, note capacity, price and availability.
6. **Think:** "I have three that fit. The goal says three. Write the comparison."
7. **Stop:** the comparison goes into the notes file.

No one wrote "drop wedding venues" in advance; the agent decided that from what it saw. That's
the value. The cost is just as visible: many model calls instead of one, a different path every
run, and a result you have to check, because a fluent comparison can still cite a price the
page doesn't show.

> 💡 **Try it:** Give a research mode (ChatGPT, Gemini or Claude) or a coding agent an
> open-ended goal from your own life, and read the steps it shows while it works. Count how many
> times it changed plan based on what it found. That's the loop.

## When agents help — and when they don't

- **Use an agent** for open-ended work where the path varies per case: "research
  these companies and write tailored outreach for each," "triage this inbox and
  handle what you can." No fixed recipe fits.
- **Use a plain automation** for predictable, fixed flows: lead → CRM → email.
  It's cheaper, faster, and more reliable. Agents add cost and unpredictability —
  don't reach for one when a simple workflow does the job.

## Common failure modes

- **The agent loops forever** → it keeps searching or retrying → no finish line or step cap →
  write "done when…" into the goal and set a maximum number of steps.
- **It picks the wrong tool** → a search where it should have read a file → tool names and
  descriptions are vague or overlap → fewer tools, each described by when to use it.
- **Different results every run on a routine job** → the job never needed an agent → the path
  was actually fixed → turn it into a workflow with an AI step.
- **It does something you didn't want** → sent, deleted or posted → it had permission it didn't
  need → read-only tools by default and approval before anything external (→ reliability).

## The honest take

Most "agent" hype is really just automation with an AI step. True agents shine on genuinely
open-ended tasks — and there, they're remarkable. The pro move is matching the tool to the
task: **fixed → automation, open-ended → agent.** Next, you'll build a real one
(→ build-a-practical-agent).
