Three tools dominate no-code automation, and being vendor-neutral here matters:
they solve the same problem for **different people**. Here's the honest map so you
pick one and stop tool-hopping.

## The three, side by side

- **Zapier** — the easiest on-ramp, the largest app catalogue, the most polished.
  Mostly linear "Zaps" (it has Paths for branching, but linear is its comfort zone).
  Brilliant for getting something working in minutes; the priciest as volume grows.
- **Make** (formerly Integromat) — a visual canvas with real power: branching (routers),
  loops (iterators), error handlers, data transforms. Excellent value and a joy to *see* your
  flow. The sweet spot for most people.
- **n8n** — **source-available / fair-code** (Sustainable Use License), **free to
  self-host**. The most flexible and the cheapest at scale, with first-class AI/agent
  nodes and a Code node for JavaScript or Python when the visual nodes run out — but a bit
  more technical. The high ceiling.

All three now ship AI steps and some form of agent feature, so "which one has AI" is no longer
the question. The questions are how the editor fits your brain, how you'll pay, and where your
data lives.

## How they charge (the shape, not the price)

Prices change often, so check each pricing page before you commit. What matters more is **what
each one counts**, because that decides how your bill grows:

- **Zapier** counts **tasks**: each successful action step is one task. A trigger plus four
  actions, run 1,000 times a month, is roughly 4,000 tasks.
- **Make** counts each **module run** (its plans now call these units credits). The same flow is roughly 5,000 units a month, because the
  trigger module counts too.
- **n8n cloud** counts **executions**: one run of the whole workflow is one execution, however
  many steps it has. The same flow is 1,000. Self-hosted n8n costs whatever your server costs.

So long, many-step flows at high volume favour n8n; short, low-volume flows barely notice the
difference, and Zapier's speed wins.

## Worked example: three people, three picks

1. **A marketer at a small shop, no code.** She wants "new Typeform entry → add to the email
   list → ping the team chat", a few dozen times a week. Every app has a ready connector, the flow
   is a straight line and the volume is tiny. **Zapier**: working before lunch.
2. **An operations lead** routing incoming orders: different branches by country, a loop over
   each line item, an error path when stock is missing. He wants to *see* the logic. **Make**:
   routers and iterators are first-class, and the canvas makes the branching legible to his team.
3. **A developer** building AI triage and agents, who wants customer data to stay on a server
   she controls. **n8n self-hosted**: agent nodes, a Code node for the odd custom step, and no
   per-step meter.

Notice each pick follows from the situation, not from which tool is "best".

> 💡 **Try it:** Open the integrations directory of Zapier, Make and n8n and search for the three
> apps you use most. Note which tools have a ready-made connector for all three. Five minutes,
> and it often settles the choice.

## Other tools you'll hear about

If your company runs on Microsoft 365, **Power Automate** may be the approved choice, and it
covers the same trigger→action pattern. Developer-leaning options like Pipedream and open-source
Activepieces exist too. The concepts in this pillar carry over to all of them.

## How to choose (pick one, go deep)

- **Simplicity & breadth** → Zapier.
- **Visual power + value** → Make.
- **Control, scale, and AI** → n8n.

Don't try to learn all three. The skills transfer (trigger → action is universal),
so commit to one editor and get fluent.

## Common failure modes

- **Tool-hopping** → three half-built flows in three tools → each switch resets your fluency →
  write down your default and only switch when a real job forces it.
- **Bill shock at volume** → a cheap flow becomes expensive when traffic grows → per-step
  metering multiplies with runs → estimate steps × runs per month before scaling, and filter early.
- **Self-hosting before you're ready** → a server that's down, unpatched or unbacked-up → nobody
  owns the ops → use n8n cloud until you're comfortable running a server.
- **Building your product inside the automation tool** → core logic that's hard to test and
  version → glue and product got mixed → keep app logic in code; let the tool handle the glue.
- **Ignoring your employer's approved list** → a security review blocks your flow → the tool
  touches company data → check what's approved before you build at work.

## The steer for this course

If your goal is **AI-powered automation** — for your own work, your team, or clients — the
two best bets are **Make** (friendliest powerful tool) and **n8n** (control, cost, and the
strongest AI/agent support). This pillar uses **n8n** for the AI-heavy lessons because of those
agent nodes — but if Make's canvas clicks better for you, the concepts all carry over. Next:
build your first real automation (→ first-automation).
