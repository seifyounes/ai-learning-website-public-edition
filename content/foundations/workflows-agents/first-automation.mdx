Enough theory — time to build. Your first automation is a rite of passage, and the
good news is that **every** automation you'll ever build is the same four steps
repeated. Do it once and the mystery is gone.

## The four steps (memorise these)

1. **Pick a trigger** — what starts the flow (a new form entry, email, schedule).
2. **Add an action** — what happens (add a row, send a message, call an app).
3. **Map the data** — wire the trigger's outputs into the action's inputs (the
   email field → the "send to" field). This is the part beginners fumble; go slow.
4. **Test, then enable** — run it with real data, confirm it's correct, *then* turn
   it on.

## A great first project

Build: **new lead (form submission) → add a row to a Google Sheet → send a Slack /
email notification.** It's simple, genuinely useful, and touches all four steps. It
maps directly onto client intake, event sign-ups, or bug reports for a side project.

One note on tools: this first build uses **Make** because its canvas is the gentlest
on-ramp — but the pillar later leans **n8n** for AI steps and self-hosting. That's fine
on purpose: the four steps are identical in both, so nothing you learn today is wasted;
you're learning the pattern, not the canvas.

## Worked example: the build, click by click

Here's the whole build in Make, written so you can follow it with the editor open. Menu names
shift a little between versions; the order of moves doesn't.

1. **Prepare the destination first.** Create a Google Sheet called "Inbox log" and type a header
   row: Name, Email, Topic, Message, Date. Headers matter: without them, most tools show your
   columns as A, B, C and mapping becomes guesswork.
2. **Create a scenario and add the trigger.** Search for your form tool (Google Forms or Tally),
   pick its "watch new responses" trigger, connect your account and choose the form. If it asks
   where to start, choose **from now on** so it doesn't process every old entry.
3. **Capture sample data.** Click **Run once**, then submit a test entry in the form. The trigger
   bubble now holds a real submission, and every field (name, email and the rest) becomes
   something you can click on when mapping.
4. **Add the sheet action.** Add Google Sheets → "Add a row", pick the spreadsheet and the tab.
   You'll see one input per column header.
5. **Map, one field at a time.** Click into the Name input and pick the *name* field from the
   trigger's output. Repeat for each column. Read every mapping back out loud: "Email column gets
   the email answer." This is the step that goes wrong.
6. **Add the notification.** Add your chat or email module and build the message from mapped
   fields, for example `New enquiry from [name] about [topic]`, with each bracket replaced by
   the mapped field.
7. **Test the whole chain.** Run once again, submit a second test entry, then check the sheet
   cell by cell and read the alert.
8. **Turn it on.** Only now switch scheduling on. Note the check interval: some triggers are
   **instant** (the form tool pushes the entry to Make the moment it arrives), others **poll**
   on a timer. You'll learn why in the webhooks lesson (→ webhooks-and-apis).

> 💡 **Try it:** Before you open any tool, draw a three-column table on paper: form field → sheet
> column → where it appears in the alert. Five minutes, and step 5 becomes copying, not thinking.

## Why testing isn't optional

An automation runs unattended, again and again. A tiny mapping mistake doesn't
happen once — it happens to every record. So you always test with real data first.
This is the automation version of the coding-agent habit "give it a way to verify."

## Common failure modes

- **"Run once" sits there doing nothing** → the trigger is waiting for a *new* entry → no fresh
  data arrived → submit a test entry *after* you start the run.
- **Data lands in the wrong columns** → wrong field mapped, or no header row → you mapped from
  memory, not from sample data → add headers and re-map from the captured sample.
- **A flood of old rows** → the trigger processed past submissions → the start point included
  history → choose "from now on" and remove the duplicates.
- **Perfect in testing, silent in real life** → the flow was never switched on, or it polls
  rarely → enabling is a separate step → turn it on, check the interval, send one live entry.
- **Dates look wrong** → a different format or time zone than the sheet expects → tools pass
  dates as text → format the date explicitly in the mapping.

## You just unlocked the pattern

Pick trigger, add action, map data, test. That loop builds most no-code automations; complex
ones are just more steps and some branching. Next we make these flows *smart* by dropping an AI
step into the middle (→ ai-in-automations).
