**Claude Code is an *agentic* coding tool.** "Agentic" is the whole idea, so start there:
you hand it a goal in plain language — "add a settings screen," "find why the build got
slow," "map this repo" — and it does the work a developer does. It reads your files, forms a
plan, edits across the project, runs commands, reads the output, and corrects itself.
Underneath every session is one loop — **gather context → act → verify** — repeated until the
goal is met. That's the line between an *agent* and *autocomplete*: autocomplete finishes the
keystroke you're typing; an agent owns the task.

The second half of the definition is *where* it works. Claude Code lives in your **terminal**
(and inside editors like VS Code), so it acts on your **real** codebase — the actual files,
the actual test command, the actual git history — not a copy pasted into a chat window. That's
why it can run your tests and react to a real failure instead of guessing. It's deliberately
**low-level and unopinionated**: no forced UI, no proprietary workflow, so it composes with the
tools you already run. The video above shows this in a live terminal — the fastest way to *get*
it. How to *drive* that loop well is its own lesson (→ core-loop); teaching it your project with
a `CLAUDE.md` is another (→ claude-md-and-memory). Here we answer the question that comes first:
what it is, and when it's the right tool at all.

## The four ways to code with AI

Be **tool-fluent, not tool-loyal** — this course is vendor-neutral on purpose, and this is
where that matters most. There are roughly four categories, and the strongest engineers move
between them per task:

- **Agentic CLI tools — Claude Code & OpenAI Codex.** You hand over a *task*; the agent
  explores, plans, edits across files, and runs commands. Best for multi-file work, refactors,
  exploration, and automation you can script. Codex is the closest sibling, built on OpenAI's
  models — and in a Claude-Code-first setup it's a **complement, not a competitor** (CC drives,
  Codex reviews and rescues → codex-inside-claude-code), not a coin-flip between two rivals.
- **AI-native editors — Cursor & Windsurf.** Chat and editor fused in
  a GUI. Best when you want to stay hands-on, watch every diff, and steer file-by-file. Often
  lets you pick among models.
- **Autocomplete + assistant — GitHub Copilot.** Widely deployed: inline completions
  plus chat and an agent mode, wired into GitHub and every major IDE. Best when you live in
  GitHub and want ambient help *everywhere* with near-zero setup.
- **App-builders — v0.app, Lovable, Bolt.** Prompt-to-app: describe it, get a working UI in
  minutes. Best for prototypes, landing pages, and starting points — the trade-off is less
  control and harder long-term maintenance.

The fifth thing you'll still use daily — a plain **chat assistant** — isn't really "coding": no
repo access by default, ideal for thinking, explaining, and drafting. Keep it in the mix for
what it's good at (more below), but it's not one of the four ways to put an agent on your code.

## When to reach for Claude Code — and when not

Choose **per task, not forever**:

- **Reach for it when** a whole job spans several files; the codebase is unfamiliar and needs
  mapping; the work involves *running* things — tests, builds, scripts — and reacting to output;
  or you want your standards encoded once and followed every time.
- **Don't reach for it when** it's pure ideation or learning with no code to touch (a chat
  assistant is faster), or a one-character tweak you'd just type yourself. And on a critical repo
  you haven't fenced yet, start on a branch and review every change until you trust the loop —
  the safety model that makes hands-off delegation safe is the next lesson (→ install-first-session).

Rule of thumb: if you can describe the entire change in one sentence, you don't need an agent;
if the job is a *task*, you do. The reassuring part is that almost everything in this pillar —
prompting, context engineering, `CLAUDE.md`-style memory, and especially **MCP** — is a shared
or open standard, so getting good with Claude Code transfers to any of these tools. Loyalty is
to the craft, not the brand.

## The 2026 surface, in one breath

The launch-era intro above nails the core idea; the tool has since grown a deep surface you'll
meet lesson by lesson. Persistent memory (`CLAUDE.md`), reusable **Skills** and **plugins**,
**subagents** and **agent teams** that work in parallel, **hooks** that fire on events, **MCP**
to reach external systems, **plan mode** and spec-driven development, an **auto mode** with OS
sandboxing that trims the approval clicks, and `/goal`, routines, and headless runs for autonomy
at scale. Don't memorize the list — just know the ceiling is high and none of it changes the
definition. The rest of this pillar is a guided climb up it.

The mental model to keep: **Claude Code is a teammate you delegate to, not an autocomplete you
nudge.** Everything that follows is about delegating well — giving it context, a clear plan, and
a way to verify its own work.
