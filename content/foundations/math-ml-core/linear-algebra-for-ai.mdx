**You need:** high-school algebra: multiplying, adding and reading a short formula. No
calculus, and no linear algebra beyond what this lesson builds.

If you met linear algebra in school, it was probably determinants, row reduction and
eigen-homework; if you never did, you start with nothing to unlearn. This lesson is the **AI
re-read**: four objects, seen as the machinery inside every model you call.

## Vectors: meaning as direction

An **embedding** is just a vector: a point in a space with hundreds or thousands of
dimensions. The whole trick of modern AI retrieval is that *similar meanings become nearby
directions*. The one operation you need is the **dot product**: multiply matching coordinates
and add them up. It's big when vectors align and near zero when they're unrelated. Divide by
the two lengths and you have **cosine similarity**, the number most semantic search and RAG
systems rank by.

> 💡 **Try it:** in your head — if cos(a,b) = 1, the texts mean nearly the same thing; what
> does cos(a,b) ≈ 0 mean? (Unrelated, not opposite — that would drift negative.) This is
> exactly the intuition you'll use to debug "why did my RAG retrieve garbage."

## Worked example: rank two documents by hand

Real embeddings have hundreds of dimensions, but the arithmetic is identical in three. Say a
query embeds to **q = (1, 2, 0)** and two documents embed to **A = (2, 3, 1)** and
**B = (0, 1, 3)**.

1. **Dot products.** q·A = 1×2 + 2×3 + 0×1 = 8. q·B = 1×0 + 2×1 + 0×3 = 2.
2. **Lengths** (square root of the sum of squares). |q| = √5 ≈ 2.24, |A| = √14 ≈ 3.74,
   |B| = √10 ≈ 3.16.
3. **Cosine.** cos(q, A) = 8 ÷ (2.24 × 3.74) ≈ **0.96**. cos(q, B) = 2 ÷ (2.24 × 3.16) ≈
   **0.28**.

Document A wins: its arrow points almost the same way as the query. Notice what you did *not*
need: any idea what each coordinate "means". That's the point. A vector database does exactly
these three steps, just across millions of documents, with clever indexing so it doesn't have
to compare every pair.

## Matrices: functions, not tables

Stop seeing a matrix as a grid of numbers; see it as a **function that moves space** —
rotating, stretching, projecting. A neural-network layer is literally
`output = activation(W·x + b)`: the matrix W *is* the learned function. Training a model means
finding good numbers for these matrices.

Count one: a layer that maps a 4,096-wide vector to another 4,096-wide vector needs a
4,096 × 4,096 matrix, about **16.8 million** numbers, plus 4,096 biases. Stack enough layers
like that and you reach the billions behind a "7B model".

## Attention is three matmuls in a trench coat

Transformers compute **Q**ueries, **K**eys and **V**alues from your tokens (three matrix
multiplications), then score every token against every other with **QKᵀ**, softmax the
scores, and blend values with a final multiply. That score matrix is n × n. At 1,000 tokens
it holds a million scores per attention head per layer; at 2,000 tokens, four million. The
quadratic cost of context windows is a matrix **shape**, not a business decision.

## Rank: the idea that makes fine-tuning cheap

The **rank** of a matrix is how much independent structure it really has. LoRA's entire bet:
the *change* you need to make to a giant weight matrix during fine-tuning is **low-rank**, so
instead of updating 16.8M numbers you learn two skinny matrices holding ~65K. You'll meet this
again in the fine-tuning lesson (→ fine-tuning-fundamentals); now you know *why* it works.

## Common failure modes

- **Rankings look random** → the query and the documents were embedded with different models
  (or versions of one), so their spaces don't line up → re-embed everything with one model and
  store the model name next to each vector.
- **Long documents always win** → raw dot product without normalization, so bigger vectors
  score higher regardless of direction → use cosine, or check that your vector store's distance
  setting matches what the embedding model recommends.
- **The right document ranks fifth** → its chunk covers several topics, so its vector averages
  them and points nowhere in particular → split into chunks of one idea each and re-check the
  scores.
- **Long prompts cost far more than expected** → a linear mental model of attention → remember
  the n × n matrix; trim, summarize or retrieve instead of pasting everything.

## Why this pillar exists

None of this is prerequisite trivia. Each object maps to a production concern you already
have: dot products → retrieval quality, matrix sizes → cost and latency, rank → cheap
fine-tuning. When the math connects to the bill, it sticks.
