This is the lesson for **building real iOS and Android apps.** The big shift is that you no
longer need separate native teams or months of setup: one codebase plus AI can get you to both
stores. What hasn't changed is that phones are fussier than browsers. Builds, permissions and
devices are where mobile projects stall, so this lesson spends its time there.

## One codebase, both platforms

- **Flutter**: Dart, one rendering engine, a consistent and polished UI. One codebase produces
  both Android and iPhone builds. Choose it when native feel and UI consistency are the
  priority.
- **React Native + Expo**: the alternative when **code sharing with web** is the goal. One
  TypeScript codebase for iOS, Android *and* web, with Expo handling previews, builds and
  native-feature access. The right tool when the product is web-first or the team lives in
  JavaScript.

The win either way: maximum reach for minimum duplicated work.

## AI builds mobile too

Everything from the web lessons transfers:

- **Claude Code, Cursor, Codex or Copilot**: generate screens, navigation and native-feature
  code, then engineer it properly. The primary video is exactly this loop on Flutter.
- **Bolt (with Expo)**: scaffold a working React Native app from a prompt, then refine it.

The genuinely mobile-specific knowledge is device setup, native permissions, store builds and
testing on real hardware. That's what this lesson adds; AI handles the boilerplate around it.

## Worked example: first screen on a real phone

Here's the path from nothing to your own app on your own phone, for each stack.

**Expo (fastest start, any computer):**

1. Install Node.js, then create a project with `npx create-expo-app`.
2. Run `npx expo start`. A QR code appears.
3. Install **Expo Go** on your phone and scan it. Your app opens on the device, and each save
   reloads it.
4. Ask your agent for one screen (the task's list screen is a good first one) and watch it
   appear on the phone.

Expo Go covers a lot, but a library with its own native code needs a **development build**.
When the agent suggests a package, ask whether it works in Expo Go.

**Flutter:**

1. Install the Flutter SDK, plus Android Studio for the Android tools (or Xcode, on a Mac).
2. Run `flutter doctor`. It lists exactly what's missing. Fix those lines first; paste any you
   don't understand to your agent.
3. Plug in an Android phone with USB debugging on (or start an emulator) and run
   `flutter run`.
4. Same next step: one screen from the agent, checked on the device.

Whichever path you take, write every snag into a "Build & run" section of the instruction file
as you go. The task below asks for it, and it pays off the second time.

> 💡 **Try it:** Already have Flutter installed? Run `flutter doctor` now and paste the output
> to any assistant with "explain each warning and whether it blocks Android, iOS or neither".
> On Expo, `npx expo-doctor` does a similar health check.

## What agents get wrong on mobile

Agents write mobile code fluently, but a few mistakes recur:

- **Permissions.** Camera, microphone, location and notifications need platform declarations
  (`Info.plist` on iOS, `AndroidManifest.xml` on Android) plus a runtime request. Code that
  skips them may compile and then fail on a device.
- **Mixed patterns.** Without a stated convention, the agent may use two state-management
  approaches in one app. Name yours in the instruction file.
- **Device realities.** The on-screen keyboard covering inputs, safe areas around notches,
  slow networks. Emulators hide some of these, so test on a real phone.

## Common failure modes

- **A wall of build errors** (Gradle, CocoaPods, SDK versions) → toolchain mismatch → run
  `flutter doctor` or `npx expo-doctor`, give the agent the full error, and record the fix.
- **Works in the emulator, crashes on the phone** → missing permission declarations or real
  hardware differences → audit permissions for both platforms and test on a device every time.
- **A package won't run in Expo Go** → it includes native code → create a development build,
  or pick a package that works in Expo Go.
- **iOS seems impossible from Windows** → iOS builds need macOS → use Expo Go and EAS Build, or
  a cloud CI service, and get Android working first.

## Reuse what you've built

Your **backend** from the last lesson (Supabase, Firebase) serves mobile *and* web, so you
don't rebuild it. Your **spec**, **prompting** and **coding-agent** skills all apply. Mobile
isn't a new world; it's the same workflow pointed at a new target. Next: making sure it
actually works, with testing and QA.
