If you learn one thing in Obsidian, learn this. Notes written in **markdown** are nice;
notes that **link to each other** are a second brain. Linking is the skill that turns a pile
of files into a thinking tool.

And in this vault it does double duty. The brackets you type are **navigation for you and a
graph for the AI** — the structure a coding agent walks when it files a
new source, decides what an existing page should point at, or hunts for pages nothing
references, and the trail a chat assistant follows through the notes you upload. Every link is
both a shortcut and a piece of machine-readable structure. That's why this is the lesson
everything else stands on.

## Markdown in 30 seconds

Markdown is just plain text with light symbols: `#` for headings, `-` for lists,
`**bold**`, `> quotes`, and `` `code` ``. It's the same format AI assistants use for their
replies and instruction files. It's portable, fast, and future-proof — and Obsidian renders it
live as you type.

> 💡 **Try it:** in any note, type `[[` and the first letters of a note you already have.
> Pick it from the list, then open the note you linked to and find the backlinks panel. Your
> link is already listed there, and you never touched that note.

## The real magic: `[[wikilinks]]`

Type `[[` and start a note's name to link to it. That single habit unlocks everything:

- **Backlinks** — open any note and a panel shows *every* note that links to it.
  Connections are bidirectional and automatic; you never maintain them.
- **Link to nothing yet** — link to a note that doesn't exist, and Obsidian creates it when
  you click. In graph view it shows as a dark-grey circle until then, which makes your open
  questions visible instead of theoretical.
- **Graph view** — see your whole web of notes as a map. Clusters reveal themes you didn't
  know you had.

The video also flags a real choice at [00:38]: Obsidian can write `[[Note]]` or standard
markdown `[Note](Note.md)`. **Stay on wikilinks.** They're shorter, they survive renames,
and both Obsidian and an agent reading the folder resolve them fine. Markdown links only win
if you plan to open the same files in an editor that has never heard of Obsidian.

## Two variants you'll need within days

- **Display text** — `[[Portfolio site|the site]]` links to the "Portfolio site" note but
  shows "the site", so sentences stay readable. This is what the video demonstrates with the
  pipe. The *actual* alias feature is different: an `aliases` entry at the top of a note gives
  that note extra names, so `[[Portfolio]]` resolves to "Portfolio site" from anywhere. Aliases have lived
  in front matter for years; what Obsidian **1.4** (2023) added was the **Properties**
  editor, the typed UI that surfaces them instead of making you hand-write YAML. You start
  writing properties in lesson 6 and query them in lesson 7 — for now just hold the
  distinction: one renames a *link*, the other renames the *note*.
- **Embeds** — `![[Portfolio site]]` (note the `!`) doesn't just link, it **shows the note's
  content in place**. It works for headings (`![[Note#Section]]`), for blocks you've tagged
  with `^an-id`, for images (`![[shot.png|300]]` to resize), and for PDFs
  (`![[paper.pdf#page=4]]`).

Link when the reader might jump; embed when they shouldn't have to.

## Why this beats folders

A file lives in exactly one folder. An idea belongs to many contexts at once — a client, a
project, a technique, a date. **Links let a note exist everywhere it's relevant**, which is
how your brain actually works. Folders organise *storage*; links organise *meaning*.

That's the same split you set up in lesson 2. The seven top-level folders declare who owns
what. Everything about what a note *means* — and every path between notes — is carried by
links.

## Why the agent cares more than you do

You can find a note without links; search is fast. The agent's job is different. When it
ingests a new source it has to answer "what does this connect to?", and the only evidence it
has is the links already in the vault. So:

- A densely linked note gets **found and updated**. An unlinked one gets quietly duplicated,
  because nothing pointed the agent at it.
- Every `[[link]]` to a page that doesn't exist yet is a **to-do the agent can see** — a
  concept you've referenced but never written up.
- Missing cross-references are exactly what lesson 10's clean-up pass looks for: orphan
  pages, and pages that clearly belong together but never point at each other.

**Don't code?** The links pay off the same way when you upload notes to a chat assistant: it
can only follow connections you made explicit. And Obsidian finds missed links on its own:
the backlinks panel's **Unlinked mentions** list shows every note that names this one without
brackets.

## Common failure modes

- **Two notes for the same thing ("JS" and "JavaScript")** → you linked by whatever name came to
  mind → pick one title and add the other as an `aliases` property.
- **Links break after you rename a note in your file explorer** → Obsidian updates links
  automatically only for renames done inside the app → rename and move notes in Obsidian.
- **Everything gets linked, so links mean nothing** → you bracketed every noun → link things
  you'd actually want to jump to or collect notes about.
- **An AI "tidies" your notes while linking** → the prompt didn't forbid rewording → say
  "insert brackets only" and ask for a plan first, whether it's an agent editing files or a
  chat assistant handing back a rewritten note.

So the habit to build: whenever you write a noun that is (or could be) its own note — a
person, project, concept, tool — wrap it in `[[ ]]`. Do that for a week and your vault stops
being a folder and starts being a graph. Next we make sure ideas actually get *in* there
every day: capture, daily notes, and the first prompt that drains your inbox for you.
