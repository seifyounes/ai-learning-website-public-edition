Uploading a spreadsheet and asking a question in plain English is one of the most useful things a
chat assistant can do for someone who doesn't code: totals by month, the five biggest customers,
which products lose money, a chart for a slide. It pays off whenever the answer is sitting in a
file you have but would take an hour of filters and pivot tables to get out. It also fails in a
particular way: **the wrong number looks exactly like the right one.** This lesson is about getting
the speed without inheriting that risk.

## What happens when you upload a file

There are two very different ways an assistant can handle your file, and the difference decides
whether you can trust the numbers:

- **It reads the file as text** and answers from what it sees, as it would with an essay. Fine for
  "what is this document about?", unreliable for arithmetic over hundreds of rows.
- **It writes and runs code** in a sandbox, usually Python, which loads the file, filters and
  totals it, and draws charts. The calculation is then done by a program, and you can ask to see it.

For any question with a number in the answer, you want the second. The big three all offer it, in
different shapes:

- **ChatGPT**'s data analysis runs Python in a notebook-style environment, can show the code and
  tables it used, and draws charts, some of them interactive. OpenAI's own help page warns it may
  not read exact values reliably from scanned or image-based tables.
- **Claude** runs code in a sandbox too. The setting is currently called code execution and file
  creation (an earlier version was called the "analysis tool"), and it can also produce Excel
  files with working formulas.
- **Gemini** analyses uploaded spreadsheets and CSVs and can chart them, and it also works inside
  Google Sheets from a side panel. Google has also announced code execution for Gemini Notebook
  (formerly NotebookLM).

Plans, file-size limits and feature names change often, so check the current docs for whichever
you use.

## Describe the data before you ask

An assistant sees column headers, not meaning. "Amount" could be pounds or units; "date" could be
order date or ship date; a final row could be a total that doubles everything. Before your first
question, tell it **what one row is, what the key columns mean with units, the time period, and
any quirks you know about**. Then make it describe the file back to you and list problems before
it analyses anything, as the video does. Clean structure helps too: one header row, one record
per row, no merged cells or blank rows splitting the data.

## Verify by recomputing one number

The core habit: **pick one number from the answer and recompute it yourself** with a filter, a SUM
or a pivot table. Start with easy ones (row count, date range, a column total) before you trust
hard ones. If the easy numbers disagree, stop; something was misread. Also ask "explain the
formula you used" for any metric: margin, growth, average. Many wrong answers are a reasonable
formula that isn't the one you meant.

## Charts

Ask for a specific chart: type, what goes on each axis, units, and a title that states the finding
("Online sales overtook in-store in Q3"), not just "Sales by channel". Check the axis starts at
zero for bar charts and that the categories add up to the total you verified. A chart is a
picture of the analysis; it inherits every error in it.

## Worked example: a small shop's year of orders

A shopkeeper uploads a CSV of 2,400 orders and writes: "Each row is one order. Amount is in euros
including VAT. Status can be paid, refunded or test. Question: which month had the highest paid
revenue?" The assistant inspects the file and reports 37 test orders and 3 rows with no date. They
ask for check numbers: row count, first and last date, total paid revenue. They match the
spreadsheet. The answer comes back as November; the shopkeeper recomputes November's paid total
with a filter and gets the same figure, then asks for a bar chart of paid revenue by month. Fifteen
minutes, and every number is one they can defend.

> 💡 **Try it:** upload any spreadsheet and ask only "How many rows of data are there, and what
> does one row represent?" Compare it with what you know. If it's wrong, every later answer would
> have been wrong too.

## Common failure modes

- **Totals are slightly off** → a totals row, duplicates or test data were counted → describe the
  quirks and ask it to reconcile grouped totals back to the rows.
- **Numbers from a PDF don't match the document** → the table was a scan or a complex layout →
  use a spreadsheet or text-based export, and spot-check extracted values.
- **It answers about part of the file** → the file was too large or had several sheets or hidden
  ones → ask which sheets and rows it used, or split the file.
- **A confident "why" appears** → the model explained a pattern the data can't explain → keep
  the finding, drop the cause unless you have evidence (→ verification-and-grounding).

## What not to use it for

Don't upload what you're not allowed to share: customer records, staff data, health or financial
details about real people, or anything under a confidentiality agreement. Check your
organization's approved tools, and use a scrubbed copy when you only need the method
(→ privacy-and-setup). Don't let it make the decision: it can tell you which product lost money,
not whether to drop it. And for a report you'll repeat every month, take the method out of the
chat and into the spreadsheet (→ analytics-reporting).
